# 고변동 선별·개별종목 투자자 합계 점검 — 2026-10-07

## 결론

고변동 선별은 정상적인 이력 부족과 조회 오류를 모두 `None`으로 처리하고, 100종목 중 하나만 점수가 없어도 전체 갱신을 막고 있었다. 정상 제외와 조회 오류를 분리하고, 오류 종목만 최초 조회가 끝난 뒤 순차로 한 번 재시도하도록 수정했다. 목록 조회 실패·미해결 조회 오류·상위 N개를 뽑을 수 없는 경우는 계속 실패 처리하며 기존 공개 JSON/보고서를 보존한다.

삼성전자·SK하이닉스의 개인+외국인+기관 합계가 큰 음수인 현상은 비교 가능한 KRX 12009 거래대금에서도 확인된다. 큰 부분이 **기타법인의 순매수** 및 기타외국인 수급과 상쇄된다. 세 분류는 전체 투자자를 포괄하지 않으므로 그 합계를 0으로 맞추는 보정은 하지 않는다. 코드의 세 투자자 필드 매핑 오류는 확인되지 않았다. 다만 개별주 원화 금액은 **순매수 수량×종가 추정값**인데 기존 설명이 이를 모두 실측이라고 표현한 오류는 수정했다.

## 확인 범위와 출처

- 대시보드 기준 버전 `e4949f01`, 공개 스냅샷 작성일 2026-10-07, 두 종목의 마지막 거래일 2026-10-06.
- 네이버 두 종목 원문을 각각 한 번씩 **순차** 조회. 개인/외국인/기관 수량을 저장 스냅샷과 대조한 종목당 최근 60행(총 120행)에 불일치 0건. `individualPureBuyQuant`, `foreignerPureBuyQuant`, `organPureBuyQuant` 필드 매핑을 확인했다.
- [krx-month-paste 기준 버전 7ff60ba991af](https://github.com/sunbininfokim-yeon/krx-month-paste/tree/7ff60ba991af785bd3595c777d55c88e770021ac)의 `data/normalized/krx_12009_stock_investor/year=2026/month=09/part.jsonl.gz` 및 `data/manifests/krx_12009_stock_investor.json` 사용. 입력 압축 파일 SHA256이 manifest와 일치한다.
- 같은 종목·날짜의 중복 재수집 행은 `collected_at` 최신 순으로 선택(동일 시각이면 파일의 마지막 행). 9월 1~21일 **15거래일×2종목=30건** 비교. 최초 중복 포함 38건으로 과대 계산하지 않았다.
- KRX 파일의 최신 날짜는 **2026-09-21**. 따라서 9월 22일 이후, 특히 10월의 기타법인·기타외국인 수급은 이 자료로 확인하지 못했다. 네이버 수량의 저장/매핑 일치와 KRX 거래대금 대조는 별개의 확인이다.
- KRX 신규 대량 수집이나 실시간 100종목 선별은 실행하지 않았다. 최신 기존 Actions run `37585035899`는 100/100 산출 및 전체 단계 갱신 성공이었다. 수정 필요성은 재현 테스트와 실패 처리 경로로 확인한 것이며, 마지막 실행이 실패했다는 뜻은 아니다.

KRX 투자자별 개별종목 거래실적의 공식 화면은 [KRX 정보데이터시스템](https://data.krx.co.kr/contents/MDC/MAIN/main/index.cmd)에서 확인할 수 있다. 아래 수치는 실시간 KRX 재조회 결과가 아니라 위 저장소의 보존·정규화 자료를 대조한 결과다.

화면 값과 KRX 값은 동일한 금액 필드가 아니다. 실제 순매수 거래대금은 매수금액−매도금액이며, 순매수 수량×종가는 그날의 매매 가격 차이를 반영하지 않는다. 위 차이를 단위 배율 오류라고 판단하거나 두 값을 억지로 일치시키지 않았다. 정규화 자료에는 삼성전자 매수 백만원/매도 원 단위가 섞인 경우의 보정 내역이 있어, 이미 KRW인 열에 백만원 배율을 다시 적용하지 않았다.

30건 모두 각 투자자 `buy−sell=net`이 정확히 성립한다. 다섯 투자자 순매수 합계와 파일의 시장 전체 순매수 값 사이 최대 차이는 **300만원**으로 백만원 단위의 개별 항목 반올림 범위에 해당한다.

별도 원자료 점검 대상도 있다. **하이닉스 9월 18일**은 다섯 분류 합계와 저장된 전체 순매수가 모두 **+4.78억원**이다. 이는 해당 저장 파일 자체의 전체 매수/매도 불균형이며, 1조원 수준의 세 주체 음수와는 규모가 다르다. 0으로 지우지 않았다. 해당 행의 원본 매수·매도 Excel, 조회 시점/시장 범위·단위 처리는 추가 확인이 필요하다. 이 감사만으로 공식 원자료 자체가 틀렸다고 단정하지 않는다.

기타법인의 큰 매수를 곧바로 자사주 매입으로 단정하지도 않는다. 매수 주체의 정확한 실체·원인은 이 투자자 분류 자료만으로 확인되지 않는다.

## 고변동 선별 수정 계약

- 최초 가격 조회 방식은 유지. 최초 조회 풀이 완전히 끝난 후 재시도를 시작한다. 목록은 추가 조회하지 않는다.
- 유효한 종가 이력에서 수익률 관측이 15개 미만이면 `insufficient_history`로 제외한다. 신규 상장 등 이력 부족에 해당할 수 있으나 상장일 자체를 확인했다는 뜻은 아니다.
- 16개 이상 관측된 기간 전체 거래량이 0이면 `no_trading_volume`으로 제외한다. 장기 거래정지 등에 대응하지만 법적 거래정지 상태를 확인했다는 뜻은 아니다. 거래량이 없는 횡보와 거래량이 있는 변동성 0인 종목을 구별한다.
- 비어 있는 응답, Close 열 누락, 잘못된 가격/거래량, 조회 예외는 정상 제외로 간주하지 않는다. **실패한 종목만 시총 순서로 순차 1회 재시도**, 각 재시도 전 1초 간격. 재시도용 병렬 실행기는 없다.
- 여전히 조회 오류가 남거나 산출 가능한 종목이 top-N보다 적으면 기존처럼 `KospiUniverseError` → 기존 JSON/Markdown 보존 → exit 1 및 Actions 오류 annotation.
- `universe_meta.high_vol_in_marcap_top`에 `excluded_n`, `excluded`(종목·사유·관측 수), `retried_n`, `retries`(최초 사유·최종 상태)를 기록. 고변동 순위는 정상 제외를 뺀 산출 가능 종목 기준임을 설명에 명시한다.
- 개별주 블록에 `net_shares_quality=observed`, `net_krw_quality=estimated`, `net_krw_method=net_shares_times_close`, 세 주체의 범위 설명 추가. 기존 수량·금액 열은 유지하며 잔여 수급을 추정해서 채우지 않는다. 시장 전체 KOSPI 거래대금 자료와 개별주 종가 환산값은 구분한다.

## 재현·검증

`audit/stock_investor_balance_2026-10-07.json`에 입력 버전·SHA256, 종목별 네이버 수량 확인 결과, 30건의 날짜별 금액·단위·원본 SHA·산술 잔차를 보존했다. 원본 API 캐시나 인증정보는 커밋하지 않는다. KRX 파일을 해당 버전에서 읽고, ticker/date별 최신 collected_at을 선택한 뒤 다음을 계산하면 재현할 수 있다.

```text
three_net = retail_net_krw + foreign_net_krw + institution_net_krw
five_net = three_net + other_corp_net_krw + other_foreign_net_krw
classification_residual = five_net - market_total_net_krw
snapshot_three_estimate = Σ(actor_net_shares × that_day_close)
```

검증: market_microstructure 오프라인 테스트 121개, UI 데이터 계약 통과. 테스트는 정상 제외·두 오류의 순차 복구·재시도 후 정상 제외·재시도 실패·유효 종목 부족·거래량 있는 변동성 0·기존 공개 산출물 보존을 검증한다. 네이버 세 주체 합계를 임의로 0으로 보정하지 않으며 원화 환산이 추정값이라고 표시하는 것도 검증한다.

## 반영 범위와 남은 확인

수정은 데이터 생성 코드·테스트·감사 기록에 한정된다. 기존 일일 파이프라인은 같은 함수를 사용하므로 병합 후 해당 수집 단계에 적용된다. UI/Worker/배포 workflow와 현재 공개 JSON은 편집하지 않았다. 새 산출물의 금액 설명 및 제외/재시도 내역은 다음 정상 데이터 생성 때 반영된다.

KRX 12009의 9월 22일 이후 자료, 특히 10월 1·2·6일을 원본 저장 계약대로 갱신하면 동일한 다섯 분류 대조로 최신 음수 원인을 직접 확인할 수 있다. 하이닉스 9월 18일의 원본 Excel 두 파일 SHA는 감사 JSON에 기록되어 있어 그 불균형을 별도 추적할 수 있다. 이번 결과는 병합·실제 일일 갱신·배포 성공을 미리 주장하지 않는다.
