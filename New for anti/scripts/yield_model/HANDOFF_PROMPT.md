## 0. 무엇을 만드는가

**목표**: 특정 지역·작물의 **올해 수확량을 범위(신뢰구간)로 예측**한다.
점추정 하나를 내놓는 게 아니라 "185~197, 가장 그럴듯한 값 191"처럼 낸다.

**결과물 3가지**
1. 학습 데이터 CSV (연도 × 기상편차 변수 + 수확량)
2. 모델 아티팩트 JSON (계수 + **측정된 성능**)
3. 대시보드용 예측 JSON (아래 §7 규격)

**철학**: 정확도보다 **정직성**이 우선이다. 성능이 나쁘면 나쁘다고 보고하고,
검증 없이 "AI 예측"이라 부르지 않는다. 이 프로젝트는 이전에 실제 모델 없이
화면에 "XGBoost Model"이라 표시하던 코드를 걷어낸 이력이 있다.

## 1. 모델 구조 — 절대 바꾸지 말 것

```
수확량 = 기술 추세(technology trend) + 기상 편차(weather deviation)
              ↑                              ↑
   품종·비료·기계화·경영 개선          모델이 예측하는 부분
```

**근거**: FAO 『Review of Crop Yield Forecasting Methods』(Basso, Cammarano,
Carfagna)가 정리한 Thompson(1969, 1986).

> 대면적 평균 수확량을 시간에 회귀시켜 추세를 도출한다. 이 추세는 유전·경영
> 개선, 특히 비료 사용 증가를 포함한 기술 진보를 담는다. **추세로부터의 편차**를
> 지역 월별 기상자료와 상관시킨다.

**따라서 비료·품종 데이터를 수집하지 마라.** 추세가 이미 흡수한다. 이게 표준이다.

**모델은 Ridge 회귀(RidgeCV)로 충분하다.** 표본이 보통 30~45시즌이므로
LSTM·XGBoost·딥러닝은 쓸 수 없다 (§4 참조).

### NASA POWER (핵심 기상 소스)

```
https://power.larc.nasa.gov/api/temporal/daily/point
  ?parameters=T2M_MAX,T2M_MIN,T2M,PRECTOTCORR,GWETROOT,T2MDEW,ALLSKY_SFC_SW_DWN
  &community=AG&longitude={lon}&latitude={lat}
  &start=19810101&end={YYYY}1231&format=JSON
```
- 45년치를 **한 번의 요청으로** 받을 수 있다 (약 1~40초)
- `GWETROOT` = **Root Zone Soil Wetness (0–100cm 근권 토양수분)**. 0~1 범위
- `GWETTOP`은 표층(0–5cm)이므로 쓰지 마라
- 결측은 `-999`로 오므로 `> -100` 필터 필요

### FAOSTAT (국가 단위 수확량, 244개국 × 301품목)

```
https://bulks-faostat.fao.org/production/Production_Crops_Livestock_E_All_Data_(Normalized).zip
```
약 34MB. 압축 해제 후 `Area / Item / Element=="Yield" / Year / Value` 필터.
`encoding='latin-1'` 필수.

### NOAA ONI

```
https://www.cpc.ncep.noaa.gov/data/indices/oni.ascii.txt
```
`SEAS YR TOTAL ANOM` 4열 텍스트. 생육기에 해당하는 계절 평균을 쓴다.
북반구 여름작물은 AMJ~ASO, 남반구는 OND~FMA.

### ⚠️ Open-Meteo 토양수분은 절대 쓰지 마라

`soil_moisture_*` 시리즈에 **2025년부터 수준 이동(level shift)이 있다.**
실측 증거: 브라질 고이아스 1~2월, 강수량이 **348mm로 완전히 동일한데**
토양수분이 2024년 0.4634 → 2025년 0.3511(−24%). 물리적으로 불가능.
같은 기간 NASA POWER는 0.716 → 0.754로 오히려 상승(그해는 기록적 풍작).

이걸 못 잡으면 **−800 kg/ha 틀린 예측**이 나간다. 실제로 그럴 뻔했다.
Open-Meteo는 기온·강수·예보용으로만 쓰고, **토양수분은 항상 NASA POWER**.

## 3. 변수 설계

### (1) 모든 기상 변수는 **편차(anomaly)** — 가장 중요한 규칙

직전 **20년 이동 평년** 대비 표준화: `(올해값 − 평년평균) / 평년표준편차`

**원값을 쓰면 반드시 실패한다.** 기상 변수 자체가 수십 년 추세를 갖기 때문이다.
브라질 1차 시도에서 협실비대기 토양수분이 43년간 −0.094 하락(r_시간 = −0.63)
했는데, 원값을 넣으니 모델이 "최근일수록 나쁘다"고 학습했다. 실제 수확량은
기술 발전으로 계속 올랐으므로 결과는 **체계적 과소예측**(최근 10년 오차가
−328, −232, −178… 거의 전부 음수)이었다.

이동 평년을 쓰면 장기 기후 드리프트는 기준선이 흡수하고 **"올해가 평년보다
얼마나 이상한가"** 만 남는다. 평년 계산에는 **해당 연도 이전 데이터만** 쓴다
(미래 정보 누수 방지).

### (2) 고온은 **EDD(극한 적산온도)**, 일수 카운트 금지

**근거**: Schlenker & Roberts (2009) — 손상이 비선형이다.
옥수수 3°C까지 **°C당 −8.2%**, 대두 −5.7%. 그 이상에서 −10.4%, −10.6%로 가팔라짐.

```python
EDD = max(0, 일최고기온 − 임계온도).sum()
```

작물별 임계온도 (실측·문헌 기반)
```
옥수수 29°C   대두 30°C   밀 28~30°C   면화 32°C   쌀 33°C
```

### (3) VPD (증기압차) — 고온·건조 복합 스트레스

**근거**: Urban et al.(2015), Roberts et al.(2012), Lobell et al.(2014)

```python
es = 0.6108 * exp(17.27 * tmax / (tmax + 237.3))   # Tetens
ea = 0.6108 * exp(17.27 * tdew / (tdew + 237.3))
VPD = max(0, es - ea)
```
**일평균이 아닌 일최고기온 기준** — 작물이 실제 겪는 최대 대기 수요.

### (4) 생육단계별 창(window)

작물·반구에 맞춰 월 단위로 나눈다. 남반구는 생육기가 해를 넘기므로
`(월, 연도오프셋)` 형태로 표현하고 **수확 연도 기준**으로 라벨링한다.

```python
# 북반구 옥수수/대두 예시
STAGES = {
  "preseason": [(9,-1),(10,-1),...,(6,0)],   # 파종 전 토양수분 충전 (Thompson)
  "july":      [(7,0)],                       # 수분기 — 가장 중요
  "julaug":    [(7,0),(8,0)],
}
# 남반구 대두 예시 (수확연도 Y = 전년 9월 파종)
STAGES = {
  "planting":   [(9,-1),(10,-1),(11,-1)],
  "podfill":    [(1,0),(2,0)],                # 협실비대기 — 가장 중요
}
```

### (5) 공간 집계

주요 산지 여러 곳의 좌표에서 기상을 뽑아 **생산량 가중평균**한다.
지역별 가중치는 그 지역의 전국 생산 점유율.

## 4. 검증 — 여기서 타협하면 전부 무의미하다

### 필수 3중 장치

**① 전진검증(forward-chaining)** — `연도 < Y`로만 학습해 Y를 예측.
**이것이 유일하게 신뢰할 숫자다.** 실제 예보와 동일한 조건이기 때문.

**② 추세를 fold 안에서 재적합** — 전체 기간으로 추세를 먼저 구하면
미래 정보가 모든 학습셋에 누수된다. 반드시 fold 내부에서 다시 적합.

**③ 추세만 쓰는 베이스라인과 비교** — 기상이 "그냥 추세대로 갈 것"을
못 이기면 그 모델은 무의미하다.

### 보고 지표

```
skill = 1 − RMSE_model / RMSE_추세만        ← 핵심 지표
detrended R² = 추세 제거 후 설명력          ← 문헌의 "기상이 X% 설명"과 같은 기준
```

**해석 기준**
```
skill > +40%   우수 (미국 옥수수 +69.3%)
+20% ~ +40%    사용 가능 (겨울밀 +31.3%, 면화 +21.0%)
+10% ~ +20%    신뢰도 낮음 — 화면에 명시할 것 (대두 +18.6%, 봄밀 +13.4%)
< +10%         사실상 실패. 그대로 보고할 것
```

### 이상치 확인 필수

단일 재해년이 검증 분산의 대부분을 차지하면 R²가 부풀려진다.
미국 옥수수는 2012 대가뭄이 검증기간 편차 분산의 **75.8%**를 차지했고,
그 해를 빼면 R²가 0.906 → **0.679**로 내려갔다. **반드시 함께 보고하라.**

## 5. ⚠️ 실패 사례 — 같은 실수를 반복하지 마라

표본이 30~45시즌뿐이므로 **변수 하나 추가가 매우 비싸다.**
문헌에 나온다는 이유만으로 변수를 추가하면 대부분 성능이 나빠진다.

### 실제로 시도했다가 전부 기각한 것들

| 시도 | 문헌 근거 | 결과 | 원인 |
|---|---|---|---|
| **MODIS NDVI** | Schwalbert(2020) | 옥수수 4.28→5.31 ❌ | EDD/VPD와 정보 중복. NDVI가 낮은 이유가 곧 고온·건조 |
| **수분기(silking) 정렬 창** | 생육단계 이론 | 옥수수 4.37→8.97 ❌ | 수분기 편차 ±6~8일뿐이라 7월과 거의 겹침. 변수만 +4 |
| **파종 지연** | Thompson | 대두 소폭 개선하나 2012 의존 | 근거 불충분 |
| **춘화처리·동해·서리** | 겨울밀 가이드 | r = +0.020 / −0.104 / −0.071 ❌ | 이 지역·기간에선 지배 요인 아님 |

**공통 교훈: "새 정보인가"를 먼저 확인하라.** 기존 변수와 상관이 높으면
정보는 그대로인데 파라미터만 늘어나 순손실이다. NDVI는 추세잔차와 r=+0.801로
**단일 상관이 가장 강했는데도** 모델에 넣으면 나빠졌다.

### 검증 전에 반드시 확인할 것

```python
# 1) 설명할 변동이 존재하는가
추세제거 잔차 CV = resid.std() / yield.mean()
#   참고값: 옥수수 7.4%, 겨울밀 11.9%, 쌀(관개) 3.2~3.5%
#   3% 수준이면 통계 오차와 구분이 안 될 수 있다 → 착수 재고

# 2) 목표변수가 올바른가  (§6 참조)
# 3) 관계가 시간에 따라 변하지 않는가  (§6 참조)
```

## 6. 작물별 함정 — 실제로 겪은 것들

### ① 목표변수를 잘못 고르면 어떤 데이터도 소용없다 (면화 사례)

텍사스 면화는 **수확포기율이 연도별 4~75%**로 요동친다. 가뭄해에 농민이
망한 밭을 갈아엎으면 살아남은(주로 관개된) 밭만 측정되어 **단수가 오히려 높게
찍힌다.** 2022년은 74.5%를 포기했는데 단수 734 lb/ac로 평년(703)보다 높았다.

```
              변동계수   최악 3개년
수확면적 기준   10.0%    신호 없음
파종면적 기준   37.1%    2022·2011·2023 ← 실제 가뭄해와 일치
```

**교훈**: 가뭄이 파괴하는 게 단수가 아니라 **면적**인 작물이 있다.
`수확량 × 수확면적 / 파종면적`으로 재계산하라. 착수 전 파종/수확 면적을
비교해서 포기율 변동을 먼저 확인할 것.

### ② 비정상성(non-stationarity) — 고정 계수가 실패하는 경우 (봄밀 사례)

미국 봄밀은 처음에 **추세만 쓰는 것보다 나빴다**(−1.0%, 전체변수 −40.1%).
단일 상관은 멀쩡한데(flowering_edd r=−0.578) 모델은 무너지는 패턴.

**원인**: Lanning et al.(2010, Crop Science) — 봄밀이 **조기 파종·조기출수
품종으로 7월 더위를 회피하도록 적응**해와서 "고온→감수" 관계 자체가 약해졌다.

**해법: 20시즌 이동창** (최근 N년으로만 재적합 = 가장 단순한 시변계수 모델)
```
고정(전체)     +3.3%
최근 15년      +0.2%   ← 표본 부족
최근 20년     +13.4%   ✅
최근 25년     +10.4%   ← 낡은 규제 유입
지수가중       +6~7%   ← 이동창보다 열등
```
**지수가중이 이동창보다 나쁘다**는 게 핵심 단서다. 옛 데이터를 낮은 가중치로
남기는 것보다 **완전히 버리는 게 낫다** = 점진적 드리프트가 아니라 실제 규제 변화.

정식 시변계수(칼만/상태공간)는 n≈34에서 불가능하다.

### ③ 이 방법론이 안 통하는 작물

**관개 의존** (인도 쌀, 이집트 밀, 미시시피 델타 쌀)
→ 강수와 수확량이 분리됨. 델타 쌀은 잔차 CV가 3.2~3.5%로 옥수수의 절반 미만.
   착수 전 잔차 CV를 확인하고, 낮으면 기대치를 낮추거나 제외하라.

**다년생** (팜유, 커피, 카카오)
→ 나무 수령, 격년결실(biennial bearing), **2~3년 전 기상의 지연 효과**.
   지연변수를 포함한 별도 구조가 필요하다. 같은 모델로 묶으면 실패한다.

**시설재배** (네덜란드 등) → 외부 기상 거의 무관.

**⚠️ 문헌의 한계 (FAO 리뷰 명시)**
> 통계 모델의 결과는 토양·지형·기상 차이 때문에 **다른 공간·시간으로 외삽할 수 없다**

**지역마다 별도 모델을 만들어야 한다.** 미국 모델을 아르헨티나에 그대로 쓰지 마라.

## 8. 시즌 중 예측 — 3단계 조립

관측 → 예보 → 평년값 순으로 시즌을 채운다.

1. **관측**: NASA POWER (2~3일 지연)
2. **예보**: Open-Meteo 16일 (기온·강수만. **토양수분은 절대 금지**)
3. **평년값**: POWER 과거의 일자별(day-of-year) 정규값

**토양수분이 예보 구간에서 비면 Open-Meteo가 아니라 POWER 평년값으로 채워라.**
스케일이 달라서 섞으면 피처가 학습 분포 밖으로 튄다.

## 9. 작업 순서

```
1. 목표 지역·작물 선정
   → 문헌으로 생육 캘린더·임계온도·핵심 생육단계 확인
2. 착수 전 진단
   → 추세제거 잔차 CV 확인 (3% 미만이면 재고)
   → 파종/수확 면적 비교 (포기율 큰 작물은 목표변수 변경)
3. 수집 (collect_{region}.py)
   → 수확량 + NASA POWER 기상 + ONI → 학습 CSV
4. 학습·검증 (train_{region}.py)
   → 전진검증 + LOO + 추세 베이스라인, 이상치 영향 확인
   → skill < 10%면 비정상성 의심 → 이동창(15/20/25년) 테스트
5. 예측 (predict_{region}.py) → §7 규격 JSON
6. 문서화 — 성능·한계·기각한 시도를 반드시 함께 기록
```

## 10. 절대 하지 말 것

1. **검증 없이 "AI 예측"이라 부르기** — 반드시 전진검증 수치를 함께 낼 것
2. **Open-Meteo 토양수분 사용** — 2025년 불연속
3. **기상 변수를 원값으로 사용** — 반드시 이동 평년 대비 편차
4. **전체 기간으로 추세를 먼저 적합** — fold 내부에서 재적합
5. **문헌에 있다는 이유만으로 변수 추가** — 새 정보인지 먼저 확인
6. **LSTM/딥러닝 시도** — 표본 30~45개로는 불가능
7. **성능이 나쁜데 좋게 포장** — 나쁘면 나쁘다고 보고. 그것도 유용한 결과다
