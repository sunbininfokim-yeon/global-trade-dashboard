# PE / CR 핵심 지표 엔진 — 2026-11-09

## 범위와 상태

CR은 기업구조조정 관점이다. 신규 모듈은 공시 수치의 재현 가능한 진단을 제공하며 투자 권유, 자동 정상화 EBITDA, 자동 청산가치 또는 LBO 가격을 산출하지 않는다.

- 구현: `dart_kfa/pe_cr.py`, 계정·산업 설정 `config/pe_cr_inputs.json`, 오프라인 진입점 `build_pe_cr.py`.
- 기존 `analyze_canonical_facts()` 결과에 `pe_cr`를 추가했다. 기존 `basic_cards`, 모델, 금융업 매핑을 덮어쓰지 않는다.
- 원본→canonical 어댑터의 기본 계정 목록에 `PECR_` 접두어 계정을 추가했다. 과거 canonical JSON은 원본에서 재생성해야 이 입력들이 생긴다.
- Worker/UI/라이브 fetch/배포는 변경하지 않았다. 이 구현만으로 서비스 화면이 바뀌지 않는다.
- 테스트 자료는 합성 fixture다. 개별 기업 태그의 실측 검증 또는 전 기업 커버리지 보장이 아니다.

## 데이터 흐름

저장된 DART FY/Q1/H1/Q3 응답 또는 SEC facts
→ 국가별 canonical 어댑터(기간·재무제표 범위·통화 정규화)
→ PECR 계정 매핑 + 전기 canonical 기초잔액
→ 산업별 적용 정책
→ `pe_cr.cards`(값·계산 정의·기간·입력 근거·결측 사유)
→ 후속 서비스 어댑터 → UI

한미 통합은 출력 키·정의의 통합이지 회계기준 차이의 제거가 아니다. 원본 통화와 출처를 보존한다. USD/KRW 환산, CFO 이자분류 조정, 리스 비교조정은 이 모듈에 없다.

## PE / CR 지표 정의

| 지표 | 이번 엔진 정의 | 핵심 입력 / 주의 |
|---|---|---|
| FCF | CFO − 유형자산 현금취득 − 무형자산 현금취득 | CF; 두 투자 항목 모두 필요. 누락≠0. 리스원금·인수대금 등을 전부 차감한 자유사용현금이 아님 |
| 유형투자 차감 현금흐름 | CFO − 유형자산 현금취득 | `fcf_ppe_only`; 완전한 FCF의 대체값으로 표시 금지 |
| 이자보상배율 | 영업이익 ÷ 손익 이자비용 절댓값 | IS/CIS; 총금융원가·현금지급이자 대체 금지. 영업손실이면 음수, 이자비용 0이면 null |
| 금융원가 커버리지 | 영업이익 ÷ 총금융원가 절댓값 | ICR과 별도 키. 한계기업 판정 대용 금지 |
| EBITDA | 영업이익 + 유형자산상각 + 무형자산상각 | 기존 P1 엔진 재사용. 동일 기간·범위·단위의 별도 D&A 입력 필요 |
| FCF/EBITDA | 위 CFO 기반 FCF ÷ 양수 EBITDA | 같은 기간만. 영업이익을 EBITDA로 대체하지 않음 |
| DSO | 평균 순매출채권 ÷ 매출 × 실제 일수 | BS 기초·기말 + IS 매출. 외상매출 대신 총매출을 사용한 대용치 |
| DIO | 평균 재고 ÷ 매출원가 × 실제 일수 | BS 기초·기말 + IS 원가 |
| DPO | 평균 매입채무 ÷ 매출원가 × 실제 일수 | 실제 매입액 대신 원가를 사용한 대용치 |
| CCC | DSO + DIO − DPO | 기초잔액 없으면 계산 보류. 매출채권 및 기타채권 합계 사용 금지 |
| 운전자본 변화/매출 | Δ(매출채권+재고−매입채무) ÷ 매출 | 좁은 운전자본 정의. 계약자산·계약부채는 별도. CFO에서 또 차감하지 않음 |
| 유동·현금비율 | 유동자산 또는 현금 ÷ 유동부채 | 유동부채는 1년 내 만기 차입금과 다름 |
| 유동차입 커버리지 | 현금 ÷ 공시 유동차입금 총계 | 리스포함 총 만기커버리지·규제 LCR이라고 부르면 안 됨 |
| 매출채권/매출·CapEx/매출 | 기말 매출채권 또는 현금투자 ÷ 동기간 매출 | 비율은 0.15=15%, 배율·백분율 표시는 지표별로 구분 |

D&A는 현금흐름표 조정행 또는 주석에서 별도 항목을 확보해야 한다. 전체 상각 합계와 하위 상각액을 중복 가산하거나 충당금·손상차손을 상각비에 포함하면 안 된다. CF 상각액의 범위가 영업이익에 포함된 비용과 일치하는지도 매핑 승인 시 확인해야 한다. 이번 CLI는 검증된 주석 D&A를 자동 추출하지 않으므로 원본 기본 응답에 별도 입력이 없으면 EBITDA는 여전히 null이다.

| shipbuilding | 계약자산/매출, 계약부채/매출, FCF | 수주잔고·신규수주·선수금·이행보증 |
| construction | 계약자산/매출, 계약부채/매출, ICR | 미청구·미수공사, PF·보증·충당금 |

| financial | 기존 금융업 하위 업권 경로 유지 | 은행/증권/보험 등 기존 분류·매핑 사용; 이 모듈의 산업기업 지표는 비표시 |

키트는 관찰 지표·적용 여부 설정이지 산업별 주석 추출 완성본이 아니다. 금융 이외 산업은 호출자가 검증된 업종을 지정한다. 복합기업을 매출액만으로 자동 분류하지 않는다.

## 계정 매핑 원칙

1. `sj_div`와 정확한 `account_id`를 함께 확인한다. 동일 이름이나 CF의 이자비용 가산행을 IS 이자비용으로 사용하지 않는다. PECR 손익계정은 IS/CIS를 명시적으로 허용하고, 동일 공시·동일 개념 중복값이 다르면 보류한다. 원래 재무제표 구분은 provenance에 보존한다.
2. `config/pe_cr_inputs.json`에 DART 후보·SEC 후보를 분리했다. 표준 후보에 없는 회사 확장태그는 null로 남긴다. 회사·연도별 실측 없이 범용 fallback을 추가하지 않는다.
3. 매출채권 및 기타채권, 금융부채 총계처럼 다른 항목이 섞인 합계를 좁은 지표에 매핑하지 않는다.
4. 동일 기업·연결/별도·통화·scale=1·기간만 계산한다. 연간/분기 혼합과 최신 결측의 과거값 대체 금지.
5. flow의 누적→분기 변환은 canonical 계층 담당. BS는 차분하지 않는다. 평균잔액은 정확한 기초일이 있어야 한다. 서로 다른 정정공시의 기초잔액이 충돌하면 보류한다.
6. CF 투자취득 및 IS 비용의 표시 부호만 절댓값으로 정규화한다. 음수 잔액·비유한 값·추정 quality는 거부한다.

신규 확장태그 승인 자료: 회사/공시접수번호, 재무제표 범위, 원문 표·계정 ID, 기간, 단위, 정의, 상·하위 항목의 중복 관계, 기대값 fixture. 금액만 제공해서는 승인 불가.

## 의도적으로 미계산하는 항목

- 순부채/EBITDA: 완전한 이자부채·리스정책·현금제한 정보 및 연간/TTM EBITDA 필요.
- 1년 내 만기부채: 단기차입+유동성장기부채+사채·리스 등의 중복 없는 집계 필요. 비유동부채를 그대로 넣지 않는다.
- 1년 유동성 커버리지: 위 만기부채와 사용가능현금 정의 필요.
- DSCR: 약정 원금상환+현금이자 및 CFADS 정의 필요.
- 유지보수 CapEx: 공시 또는 명시적 사용자 가정 필요. CapEx/D&A를 유지보수투자 자체로 간주하지 않는다.
- 조정 EBITDA, 청산가치, 담보회수율, 수주잔고: 검증된 추가자료/시나리오 필요.

이 키들은 이유 있는 null이며 `visible_cards`에서 제외한다. 미구현·자료부족·업종 비적용은 UI에서 구분해야 한다.

## 사용과 Claude 인수인계

오프라인 명령: `python3 build_pe_cr.py saved_reports.json --period annual`.
입력은 `build_pe_cr.py` docstring 형식이며 결과는 stdout으로 출력한다. 외부 조회·API 키·자동 파일 저장은 없다.

기존 통합 함수에서는 `pe_cr_history=[전기 canonical ...]`, `pe_cr_industry="shipbuilding"` 등을 전달한다. 분기 CCC에는 해당 분기의 시작 직전 BS가 필요하다.

Claude는 계산식을 Worker에 재작성하지 말고 이 결과를 서빙하는 어댑터를 연결한다. 기존 서비스 `basic_cards`에 바로 붙이는 형식이 아니므로 카드별 단위/기간/series를 변환하는 경계가 필요하다. 계산 카드들은 `unit` 문자열(`money`, `ratio`, `days`), `inputs`, 평탄 기간 필드를 사용한다. EBITDA도 이 형식으로 감싸고 P1 근거는 `inputs`에 보존한다. 미계산 예약 키는 value/status/reason만 가지므로 필드 부재를 허용해야 한다. 무검증 object spread 금지. 새 계약 버전과 캐시 키를 함께 검토한다.

배포 전 필수: 제조·반도체·조선/건설·해운·금융의 저장된 실제 공시 fixture 검증, 각 후보 account_id의 의미 검증, 기존 금융 카드 유지 검증, 결과↔API↔UI 숫자 비교. 현재 합성 테스트 통과는 이 라이브 검증을 대신하지 않는다.
