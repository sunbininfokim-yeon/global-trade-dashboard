# 정책 검색 품질 보강 · 2026-10-06

기존 PR #455에 이어 구현한다. 운영 DB, 맥 색인기, 미배포 Worker/UI를 구분한다.

## 변경 이유와 결과

- 한영 별칭: 에너지·에너지 안보·원유·천연가스·LNG·전력망·원자력·재생에너지·수소·석탄·탄소 포집, 구리·알루미늄·농업·보건의료·해운·공급망 등을 공통 사전에 추가했다. 국가·관세 전용 예외가 아니다. `oil`을 원유 동의어로, `power`를 전력 동의어로 쓰지 않는다. 자연어 전체 문장을 임의의 OR 조건으로 바꾸지 않는다.
- 네 유형 후보: 문단 벡터와 기존 단일 벡터를 유형별로 조회한다. 새 문단 벡터가 있는 문서에 기존 벡터를 대신 쓰지 않는다. 키워드 근거도 유형별 후보를 확보한다. 마지막 결과 제한은 관련 후보에만 유형별 기회를 부여하며 없는 자료를 만들어 채우지 않는다.
- 순위: 유형 안에서 키워드 순위와 벡터 순위를 RRF(k=60)로 결합한다. 정확한 제목·공식 요약의 짧은 제목은 우선한다. 조건 검색은 일치 개수, 같은 구간의 근거, 의미 점수 순이다. 날짜 정렬은 기존 네 줄 안에서 유지한다.
- 조건 근거: `3/3`은 세 조건의 언급이 확인됐다는 뜻이다. 추가로 360자 구간에서 함께 발견되면 `shared_passage`, 선택한 근거가 서로 다른 구간이면 `separate_mentions`, 인용 문서에만 있거나 원문과 인용 문서에 나뉘면 별도 값으로 표시한다. 근접 언급은 법적 적용·예외·금지 대상의 확정이 아니다.
- 긴 문서: `policy-document-v2`는 SEC./SECTION 및 Sec./Section 조항 경계를 이용해 정의·권한·금지·제한·예외·적용·집행·발효 조항의 첫 문단에 본문 예산의 최대 절반을 예약한다. 나머지는 문서 전체에 분산한다. 여전히 문서당 최대 24개이며 부족한 범위는 `partial`이다. 조항 식별은 선택용 휴리스틱이며 법적 해석이 아니다.
- 운영 성능: 유형별 전체 벡터의 정확 거리 계산은 실제 DB에서 57014 시간 제한에 걸렸다. 최종 버전은 유형별 부분 HNSW 인덱스로 먼저 후보를 확보한다. 네 유형의 합산 SQL은 누적 조회 시간으로도 제한을 넘을 수 있어 Worker는 동일한 질의 벡터로 유형별 RPC를 병렬 호출한다. 질의 임베딩 API 호출을 네 번 만들지 않는다. 합산 함수는 호환용으로 남기며 기본 경로에서 사용하지 않는다. 기존 단일 벡터 조회에서도 거리 외 정렬 키를 제거해 KNN 인덱스를 사용할 수 있게 했다. HNSW는 근사 검색이므로 완전한 관련 자료 목록을 보장하지 않는다.

## 마이그레이션·권한·범위

`20261006010000_policy_search_quality.sql`은 기존 테이블·트리거를 바꾸지 않고 검색 RPC 5개와 부분 ANN 인덱스 3개를 추가한다. 법안은 기존 전역 HNSW를 재사용하며 상대적으로 적은 공법·행정명령·규정만 별도 인덱스로 분리한다. 서비스 롤만 호출하며 anon/authenticated 실행은 취소한다. SQL은 재실행 가능하고 `schema.sql`에도 동일 블록을 넣었다. 기존 컬렉션의 임베딩 열이 없는 새 DB도 건너뛰며 새 문단 벡터는 조회 가능하다. 기존 전역 벡터 인덱스는 구 버전 호환을 위해 보존한다. Supabase 편집기 시간 제한을 고려해 함수·각 인덱스를 독립 커밋한다. 벡터 GUC 등록을 위한 타입 초기화 후 함수를 생성한다. 공유 메모리 부족(53100)을 피하려고 생성은 직렬·64MB 임시 메모리로 실행한다. 운영 추가 인덱스는 규정 23MB·EO 1,096kB·공법 808kB다. 전체 DB는 1,104,514,195bytes(약 1.10GB)다.

메일·즐겨찾기·법안 단계·원격 수집 예약은 이 변경에 포함하지 않는다. 맥 실행기 대기 경계에서 문서 빌더만 갱신했다. PID를 재시작하거나 다른 실행기를 추가하지 않았다. 기존 문서를 전량 재임베딩하지 않는다. 새 문서와 변경된 문서는 v2로 처리하며 기존 문서는 기존 벡터로 검색된다.

Worker 캐시는 `us:search:v7`, UI 스크립트는 `20261006-search`로 변경했다. 웹사이트에는 병합·배포 후 반영된다. Claude 소유권 검사 대상인 `_worker.js`, `index.html` 변경이므로 기존 사용자 검색 수정 승인 범위에서 Claude 통합을 기다린다. 소유권 검사를 우회하지 않는다.

## 검증 방법과 한계

`services/policy-search/evaluation/queries.json`은 공식 출처에서 식별한 10개 문서에 대한 50개 확인 질의다. 결과를 보고 정답을 고르지 않았으며 번호 검색에 의존하지 않는다. 넓은 `에너지` 질의에는 다른 관련 문서가 먼저 나오는 것이 타당할 수 있다. 따라서 지표는 알려진 특정 문서의 상위 20개 발견율이며 전체 검색 정확도나 완전한 Recall은 아니다. WHO 탈퇴 EO는 에너지 계열 질의의 제한된 부적합 대조군이다. 모든 결과의 관련성은 판단하지 않았다.

`evaluate-live.cjs`는 수정 전 Worker/사전의 고정 복사본과 수정 후 코드를 Mac VM에서 실행하고 운영의 공개 정책 자료를 조회한다. 동일 질의의 임베딩과 REST 응답은 비공개 로컬 캐시에 보관하여 재사용한다. 키·벡터·구독자 자료는 결과 파일에 포함하지 않는다. 공식 자료의 URL과 문서 ID만 보고한다. 웹사이트 배포 검증과 다르다.

조건 검색의 의미 후보 임계값 0.65는 잠정값이다. 제한된 양성/음성 사례만으로 최적 임계값을 확정하지 않는다. 수집이 진행 중이므로 문서 원문·인용 맥락·문단 임베딩 적재의 미완료는 검색 개선과 별도 문제다.

재현 예:

```sh
POLICY_SEARCH_BASELINE_PREFIX=/private/tmp/policy-search-before-20261006 \
  node services/policy-search/evaluate-live.cjs
```

기본 환경 파일은 기존 대시보드 `.env.local`와 Google Studio 파일이며 별도 키를 채팅에 전달하지 않는다. 비교 기준 파일은 Git `d48277bb`에서 추출했다.

## 운영 적용 확인 · 2026-10-06 13:31 KST

함수 설치와 추가 인덱스 3개를 확인했고 인덱스 생성 작업은 남아 있지 않다. anon/authenticated 실행은 false다. 한 질의의 캐시 벡터를 이용한 유형별 HTTP 서비스 RPC에서 각 유형 20개를 반환했다: 법안 2,172ms, 공법 2,152ms, EO 879ms, 규정 3,476ms. 단일 질의·순차 측정이며 실제 사이트 지연이나 부하 테스트 수치가 아니다.

새 본문 색인 2,854문서(법안 2,607·공법 17·EO 17·규정 213), 문단 임베딩 22,379개, 대기 23,843건, 실패 0건이다. 기존 전체 자료의 단일 벡터는 유지한다. 따라서 새 본문 색인의 2,854건을 전체 검색 가능 자료 수로 해석하지 않는다. 새 문단 색인 326문서는 벡터 범위가 부분적이고 17문서는 본문이 없다.

## 금융·중국 주제 확장 · 2026-10-06

금융·금융시장·금융규제·은행·자본시장·증권·보험·금리·스테이블코인·자금세탁/방지·외국인투자·해외투자, 미중관계·중국공산당·국가/경제안보·인공지능·첨단반도체·수입규제·무역협정 별칭을 추가했다. 중국의 공식 국명 표기도 인식하며 대만·홍콩은 별도 조건으로 유지한다. `bank`(강둑), `security`(안보/증권), `AML`(질병 등), `PRC` 같은 다의적인 단어/약어는 해당 새 주제의 동의어로 추가하지 않았다. 검색 로그로 인기 순위를 측정한 결과는 아니며 정책 탐색용 기본 주제 확장이다.

예: `금융, 중국`, `중국, 해외투자`, `은행, 금융규제`, `스테이블코인, 자금세탁방지`. 단일 주제 검색에도 같은 사전을 쓴다. 별칭은 질의 처리에만 쓰므로 이 변경 때문에 전체 문서를 다시 임베딩하지 않는다.

폭넓은 `금융, 중국` 조건의 합산 RPC는 운영 DB에서 57014를 반환했고, 분리 호출에서도 법안의 근거 후보 200개 처리가 제한을 넘었다. 본문 검색 역시 유형별 RPC로 분리하고, 근거 후보는 `max(50,min(limit*2,200))`으로 제한했다. 최종 병렬 호출은 모두 HTTP 200: 법안 25개(두 조건 근거 25개), 공법 6개(2개), EO 7개(0개), 규정 25개(8개). 응답 시간은 각각 5,439/869/784/3,895ms다. 두 조건 일치 0개의 EO도 단일 조건 후보가 있을 수 있으며 두 조건 모두의 근거가 있다고 표시하지 않는다. 단일 질의 검증이며 부하 테스트나 검색 전체의 정확도 측정은 아니다. 중간 401/PGRST303 응답 한 건은 재확인에서 재현되지 않았다.

맥 서비스 PID 746은 실행 중이며 현재 waiting이다. 운영 `data_sync_runs`에서 Congress incremental의 14:35~14:51 KST 실행 succeeded·read/write 각 100건을 확인했고 `bills.last_synced_at`도 실제 갱신됐다. 100건은 새 발의 법안 100개가 아니라 기존 행 갱신을 포함한 처리 수다. 마지막 색인은 15:55 종료(exit 0)·464작업 처리이며 운영 색인은 문서 3,218개·문단 벡터 26,295개·대기 23,479건·실패 0건이다. 전체 DB 약 1.19GB. 다음 주기는 19:55 KST로 기록돼 있다. 이번 작업에서 수집기 재시작/중복 실행/예약 변경은 하지 않았다.

에너지 계열 20개 질의의 앞선 비교에서는 지정 문서 상위 20개 발견이 12→17개였으나 이는 금융 확장/후보 풀 조정 전의 제한된 비교다. 전체 50개 평가는 사용자의 중지 요청으로 미완료이며 재개하지 않았다. 테스트와 운영 RPC 검증, 웹 배포는 각각 별개다.

## 반도체·첨단산업 확장과 종료 · 2026-10-06

기존 반도체·첨단반도체·인공지능 조건에 반도체 장비/소재/제조, 집적회로, 고대역폭 메모리(HBM), 첨단 패키징, 첨단산업/기술/제조, 핵심 신흥 기술, 양자컴퓨팅/기술, 로봇공학, 생명공학, 항공우주 별칭을 추가했다. 광범위한 첨단산업을 모든 세부 업종과 동일 조건으로 만들지 않으며 단독 chip은 음식 등 오탐 때문에 반도체 별칭에 넣지 않았다. 예: `반도체, 중국, 수출통제`, `고대역폭메모리, 반도체장비`. 이번에는 로컬 회귀 확인만 수행하고 운영 검색/임베딩 API나 비교 평가는 실행하지 않는다.

사용자의 비용 관련 종료 요청에 따라 맥 실행기 대기 중 STOP 파일을 저장했다. 현재 자동 Congress/RSS/문단 임베딩 수집은 중단하며 기존 DB와 처리 체크포인트를 보존한다. 명시적인 재개 요청 전까지 다시 시작하지 않는다. 웹 배포와 기존 메일 발송 설정은 변경하지 않는다.

최종 사전·Worker 관련 로컬 회귀 26개 통과. GitHub Congress 수집 workflow는 disabled_manually 상태를 확인했다.
