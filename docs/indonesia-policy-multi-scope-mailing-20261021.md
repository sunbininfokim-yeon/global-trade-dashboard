# 여러 상품·지역과 전국 메일 구독 (2026-10-21)

## 사용자 동작

구독 패널에서 13개 상품 중 여러 개를 체크하고, 여러 지역 또는 **인도네시아 전국 · 중앙·모든 지방**을 선택해 한 번에 저장한다. 상품에는 석탄·니켈·팜유·바이오연료·보크사이트/알루미늄·구리·주석·코발트·망간·철광석/철강·실리카/석영·금/은·희토류가 있다. 상품 전체 선택/해제, 지역 이름 검색, 저장한 조합별 해제/재구독을 제공한다. 검색 화면의 검색어·품목 필터는 구독 설정과 분리한다.

상품 2개와 지역 2개를 고르면 4개 조합이 하나의 DB 트랜잭션으로 저장된다. 잘못된 입력이나 한도 초과는 전체 요청을 취소하고 일부만 저장하지 않는다. 기존 활성 조합을 포함해 최대 100개까지 허용하며 해제된 조합은 활성 한도에서 제외한다. 기존 구독은 새 조합을 추가한다고 지워지지 않는다.

전국은 실제 지명을 저장하는 대신 구독 범위 `__all__`을 사용한다. UI/API가 전국을 고르면 개별 지역을 함께 저장하지 않는다. 개별 지역 체크는 비활성 상태로 보존되어 전국 체크를 해제하면 다시 사용할 수 있다.

| 구독 | 관련 전국 적용 규정 | 관련 선택 지역 규정 | 관련 다른 지역 규정 |
| --- | --- | --- | --- |
| 석탄 + 동칼리만탄 | 포함 | 포함 | 제외 |
| 석탄 + 전국 | 포함 | 포함 | 포함 |
| 니켈·팜유 + 전국 | 두 상품 중 하나와 관련되면 포함 | 포함 | 포함 |

위 매칭은 **검토된 품목 AND (전국 구독 OR 전국 적용 OR 선택 지역 일치)**다. 상품을 여러 개 고르는 것은 상품끼리 AND 조건을 요구하는 뜻이 아니다. 전국 구독으로 지방 규정을 받아도 메일에는 그 규정의 실제 적용 지역을 표시한다. 지방 규정이 전국 적용인 것처럼 바꾸지 않는다. 군·시→주 관계를 추정하지 않으며, 주 구독이 그 주의 군·시를 전부 포함한다는 의미는 아니다.

## 지역 선택과 수집 범위

[BPS SIRUSA의 공개 주 분류](https://sirusa.web.bps.go.id/metadata/variabel/991eb20f-b1a9-ae36-10a3-daf62e89226e)를 2026-10-21 대조해 38개 주 이름·BPS 코드를 저장했다. `scripts/indonesia_policy/mail-regions.json`이 검토한 입력이며 한국어 이름은 화면용 번역이다. 통계 분류를 법적 적용성이나 군·시 행정 위계의 근거로 사용하지 않는다.

DB의 서비스 전용 `policy_idn.mail_regions`와 이미 수집된 지방 관할 목록을 합쳐 선택지를 만든다. 38개 주에 더해 확보한 군·시도 유지한다. 해당 지방 문서가 없는 지역은 **지방 자료 미확보 · 전국 적용 규정 포함**으로 표시한다. 구독 선택 가능, 지방 문서 존재, 지방 규정 전수 수집 완료는 서로 다른 상태다. 지방 문서 존재도 완전 원문 확보나 법적 효력 확인을 뜻하지 않는다.

## DB·메일 연결

- `public.idn_set_my_mail_subscriptions(text[],text[],boolean)`은 Auth 전용 SECURITY INVOKER 진입점이다. 비공개 `policy_idn_user` 함수가 UID·확인된 계정·입력·한도를 검사하고 프로필 행을 잠가 병렬 요청을 직렬화한다. 브라우저가 사용자 ID를 전달하지 않는다.
- 기존 단일 조합 RPC도 유지해 이전 클라이언트와 조합별 해제/재구독이 계속 동작한다. 재가입은 generation/activated_at을 새로 만들어 예전 알림을 되살리지 않는다.
- 미리보기 매칭 수, 실제 outbox 등록, 발송 직전 활성 여부가 같은 범위 판정 함수를 사용한다. 전국과 개별 지역 구독이 겹쳐도 사용자·이벤트당 outbox는 한 건이다. 특정 상품의 전국 구독으로 다른 상품 변경이 통과하지 않는다.
- 불완전 원문 보류, 검토 인용/공식 URL/적용 지역 검사, 가입 시점, 전체 정책 수신 거부, 최종 발송 게이트와 기존 US/RSS 분기는 유지한다.

운영 migration은 `20261021040724_indonesia_multi_scope_subscriptions.sql`이다. Supabase CLI로 생성한 파일을 플러그인이 실제 부여한 운영 버전에 맞춰 이름을 정렬했다. 운영 이력과 파일 SQL MD5는 `e807ee1669186a75ffdc0b868a0609ab`로 일치한다. 적용 전 비공개 백업은 `policy-downloads/indonesia-20261021/mailing/pre-multiscope.json`이다.

## 검증과 배포 경계

메일링 SQL/가짜 Resend 63개·API/클라이언트 14개·브라우저 6개와 타입 검사를 통과했다. 다중 조합의 원자 저장·100개 활성 한도·비활성 슬롯 재사용·38개 주 분류·자료 미확보 표시·상품 조건·전국/지역 중복 방지·재가입 세대·최종 해제 검사를 포함한다.

실제 운영 DB에서도 Auth 역할로 4개 지역 조합과 2개 전국 조합 저장을 확인한 뒤 모두 롤백했다. 실제 구독/사용자 설정이나 발송 대기열을 만들지 않았다. 브라우저의 구독은 가짜 Auth/RPC 검사이며 실제 로그인 계정의 종단 검증을 대신하지 않는다. UI의 1024px/390px 화면을 확인했다.

**DB 변경은 적용됐다. UI는 PR #652의 Claude 병합·배포 대상이다.** 자동 수집 예약·IDN 메일 활성화·실제 메일 발송은 이번 변경에 포함하지 않는다. 배포 후 실제 로그인 계정에서 여러 상품/지역 및 전국 저장·새로고침·해제·검토된 이벤트 수신을 확인한다. 전국은 현재와 앞으로 수집·검토된 변경을 포함하는 구독 범위이며, 아직 수집하지 않은 전국 지방 규정까지 확보했다는 뜻이 아니다.
