# 공개 원문 HTML 표 자동 수집 기반 — 2026-10-17

사용자 요청: API 밖 취합 사이트의 새 여론조사가 실제 후보별 관측으로 들어오도록 보강. 담당 `codex/poll-html-table-transport-20261017`, 시작 main `c5913923`. 이 PR에는 실제 주별 계약/수집 입력을 포함하지 않는다. VA 입력은 같은 기반 위의 독립 주별 PR이다. 병합·배포·운영 workflow 실행은 하지 않았다.

## 확인된 문제와 변경

기존 270toWin 표는 발견용이고, 기존 원문 보완은 개별 발표를 등록해야 한다. 따라서 API 밖 새 발표는 발견돼도 수치 편입이 자동으로 되지 않았다. 10/17 실제 VoteHub 1,511개 응답에 CNU/Wason VA-02 10/14 발표가 없었다. RCP 표를 통해 발견한 이 조사의 대학 원문/직접 연결 공개 Google 표를 실제 HTTP 200으로 수집했다.

새 `poll_html_tables.py`는 주별 입력의 검토 계약을 읽는다. 첫 어댑터는 CNU/Wason 공개 조사 목록 → 최근 60일 내 최신 2개 발표 → 해당 발표가 직접 임베드한 공개 질문 표 → Q4 ordinary House ballot의 All 열이다. 날짜·모집단·지리·전화 표본 합계·방법·문항·후보/정당·전체 응답합계 검사를 통과한 원문을 현행 관측 계약으로 변환한다. Q4a의 VA-02 표본 상원 문항을 VA 전체 상원 조사로 올리지 않는다. 조건부/정보제공 후/변경된 의뢰 disclosure는 보류한다. 확인한 출처 형식의 자동 대조이며 과거 정확도 등급/수기 검토로 표시하지 않는다.

공용 계약 파일은 빈 목록이다. 실제 VA 계약은 `config/state_evidence/2026/VA.json`의 `append_item` operation으로만 등록한다. 다른 주의 조사를 이 어댑터로 추정하지 않는다. 다른 기관·문서 형식은 별도 검토/어댑터가 필요하다. 같은 검토 형식의 새 날짜 발표는 매일 다시 발견·추출한다. 형식·방법·후보 변경은 자동 승인하지 않는다.

## 자동화·중복·장애

기존 `us_election_polls_refresh.yml`의 매일 06:10 KST capture/retry 실행 경로에 연결했다. workflow/deploy.yml/UI 변경 없음. API 키 추가 불필요. 현재 PR과 실제 VA 입력이 main에 들어간 후 일일 실행에 적용된다. PR 작성만으로 서비스 반영 또는 첫 실행 성공을 주장하지 않는다.

- 원래 API 응답과 표 원문 기반 기록을 분리한다. 원문 URL/SHA-256/확인 시각/추출 방법/검토 계약 지문을 함께 보존한다.
- 나중에 같은 API 파동이 들어오면 후보 별칭을 명부의 canonical identity로 대조해 1개만 센다. 표본/후보값/정당 의뢰/모집단 등이 다르면 충돌 참고 자료로 보류한다.
- 원문 장애·파싱 변경 시 원래 값/원래 날짜/원래 확인 시각을 보존하고 참고 전용으로 전환한다. 새 정상 수집이라고 날짜를 바꾸거나 결측을 0으로 만들지 않는다.
- 게시 재시도는 원자료/동적 검토/원문 영수증이 해시로 묶인 기존 체크포인트를 재사용한다. 네트워크 재조회 없이 현행 계약과 대조한다. 주별 재생성도 같은 원래 영수증을 사용한다.
