### Next — 코덱스 요청 (T19 후속)
`bills`/`executive_orders`/`regulations` 세 테이블 모두 이미 Gemini 임베딩
(`embedding`, `embedding_model`, 1536차원)을 갖고 있음. 다음 RPC를 만들어줘:

```sql
search_policy_corpus(
  p_query_embedding vector(1536),
  p_embedding_model text,
  p_result_limit integer default 20
) returns table (
  source_type text,      -- 'bill' | 'executive_order' | 'regulation'
  source_id text,         -- bill_id / eo_number::text / regulation_id
  title text,
  similarity_score double precision
)
```

- `supabase/migrations/20260901_policy_semantic_bill_relations.sql`의
  `refresh_bill_semantic_relations` 패턴을 참고: 세 테이블 각각
  `embedding_model = p_embedding_model and embedding is not null`인 행만 대상으로
  코사인 거리(`<=>`) 계산.
- 세 테이블 결과를 union해서 유사도 내림차순으로 합쳐 상위 `p_result_limit`개 반환.
- 읽기 전용 RPC. Worker(`_worker.js`의 `usSearch`)가
  `{ p_query_embedding, p_embedding_model: 'gemini-embedding-001', p_result_limit }`
  형태로 호출한다.
- 확인 요청: RPC 시그니처, 세 테이블의 실제 `embedding_model` 값이 일치하는지,
  응답 지연(ms), 실행 결과 링크.
