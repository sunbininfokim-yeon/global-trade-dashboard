# 새 주 검토일과 종전 수집일 분리

사용자 요청의 후속 주별 조사 중 ME 10/13 검토가 AL/CT/NH/NJ/NM의 10/9 재생성·테스트를 깨뜨리는 문제를 발견했다. 다른 세션도 WA의 같은 projection 오류를 독립 재현했다. 주별 입력을 수정하거나 검토일을 과거로 낮추지 않는다.

공용 기반 `codex/election-review-clocks-20261013`, base #529 `f3a28253`. 주별 packet·전국 생성 JSON·workflow·UI·main 병합·배포는 포함하지 않는다.

- 현재 명부의 검증 시계는 적용 검토일의 최대값으로 계산한다. 실제 미래 검토일은 현재 UTC일을 넘어가면 거절한다.
- 과거 packet 재생성은 현재 검토 목록을 별도 시계로 검증하되 관측 창·원래 as_of/fetched_at·영수증은 종전 값을 사용한다. 새로운 후보가 같은 주에서 바뀌면 기존 대진 검사로 관측을 보류한다.
- 전국 후보 projection의 검증일만 전체 명부 검토일로 올린다. 개별 주 evidence의 원래 창 계산일·원래 polling source 날짜는 변경하지 않는다.
- 공용 테스트 fixture는 raw JSON에 더해 적용된 주별 검토도 읽는다. 역사 시나리오의 DAY는 그대로 두고 전체 현행 명부 검증에만 SNAPSHOT_DAY를 사용한다.
- 새 검토가 미래라는 이유로 과거 다른 주 캡처를 잃던 회귀와 진짜 미래 검토 거절, 원래 시계 보존을 검사한다.

검증 결과/PR 링크는 PR 본문에 남긴다. ME와 WA는 이 공용 기반 뒤의 독립 PR이며 서로 위에 쌓지 않는다. #524 → #529 → 이 시계 기반 → 주별 입력 순서로 검토한다. AK #525·KS #526은 #524 기반의 독립 입력이며 기존 검토일이 원래 범위 안이므로 별도 선행 조건은 #524다.
