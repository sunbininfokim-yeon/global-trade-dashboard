## 실제 보강 범위

- 운영 사이트 기준 하원 후보 표시 120/435 → 최초 보강본135/435 → 현재 보강본 **435/435, 50주 전체**. 루이지애나를 제외하면 **429/429**. 루이지애나6구는 11월 전정당 선거/결선 구조로 구분한다.
- 선거하는 상원35/35 및 주지사36/36의 기존 주요 후보 대진 연결은 유지한다. 비선거 상원65석과 비선거 주지사14곳을 누락으로 세지 않는다. 이 작업에서 상원/주지사 모든 소수정당·기명 후보까지 인증했다고 주장하지 않는다.
- 하원 직접 공식 전체/활동 명부133구: CA52·FL28·MI13·NC14·NJ12·MO8·IA4·DE1·SD1. NY7구는 공식 주요 정당 자료, 나머지295구는 The Green Papers의 선거당국 확인 보고 명부다. 50주 공식 인증 완료와 전국 표시 연결을 구분한다.
- The Green Papers의 이름 기울임꼴은 선거당국 확인 미보고, 취소선은 탈락/비활동으로 해석한다. 표시 명부의 미확인 기명·소수정당40명은 후보 카드에서 제외하고 별도 기록으로 보존한다. 주요 정당 후보를 이 미확인 목록에 보류한 지역구는 없다.
- 미시간 공식 추적 명부는 하원13구+상원1곳 활동 후보68명, DISQ4명 제외. MI01 Callie Barr(DEM)·Jack Bergman(GOP) 등7명. MI04 Diop Harris → Sean McCann 정정. 새 후보에게 이전 후보의 여론조사를 넘기지 않는다.
- FEC 등록 명부로 본선 후보를 만들어내지 않는다. 공개 본선 명부가 인용한 FEC ID는 기존 공시의 동일 지역구·이름·정당으로 대조한 경우에만 연결한다. 정당/금액/경선·본선 구분은 기존 공시 계약을 유지한다.

## 수집·보존·UI 계약

- `refresh_house_candidate_rosters.py --review-public-sources`: 50주 공개 명부를 가져와 상태 범례·후보 행·기명 후보·후보 수·435구를 검증하고, 검토된 공식 주별 명부를 우선 적용한다. 소스 하나라도 실패하거나 명부가 불완전하면 원래 후보 스냅샷을 덮지 않는다. 새 이름이 자동으로 여론조사 승인이나 승자 판정이 되지 않는다.
- 공식 NC CSV, IA/NJ/MO PDF 검토 추출, SD/DE HTML의 어댑터와 검토 스냅샷을 포함했다. 원문 전화·주소·이메일은 공개 산출물에 복사하지 않고 후보 이름·정당·출처만 사용한다. PDF 원본은 임시 검토 자료이며 저장소에 커밋하지 않는다.
- `build_board.py`·`publish_federal_matchups.py` → 기존 `elections_board_v1.json`의 state.election_matchups에 실제 연결. 별도의 UI 변경 없이 후보 카드가 읽는다. polling이 없는435구 모두 기존 카드 생성기를 실행해 이름 표시를 확인했다.
- `audit_candidate_coverage.py` → `usa_candidate_coverage_v1.json`: 435/35/36 및50주 조인·출처 구분. 이 감사 파일 자체는 기존 UI가 읽는 파일이 아니며 실제 후보 표시는 기존 board에서 제공한다.
- NC01은 공식 CSV의 법적 이름 DONALD GENE DAVIS·닉네임 DON·투표용지 이름 Don Davis를 대조해 기존 Donald Davis 조사와 연결했다. TX15는 명부가 직접 연결한 현직 공식 프로필로 Monica De La Cruz-Hernandez/Monica De La Cruz를 별칭 검토했다. 실제 후보 변경 MI04는 조사 우세 표시를 계속 보류한다.
- 공식 사이트 접근 상태는 `2026_source_coverage.json`에50주별 기록. HTTP200은 후보 수집 완료로 간주하지 않는다. GA/TN/PA/NY 등의 동적 화면·403은 새 API 키 필요와 동일하지 않다. 사용자 자료 제공 없이 공개 검토 명부로 연결했다.
- 후보 명부 수집기 자체를 새 Actions 일정으로 설치하지 않았다. 현재 검토본이 board 재생성에 유지되며, 수집기는 명시적인 자료 검토 실행을 제공한다. 일일 polling 자동화는 별도 PR #489이고 양쪽 모두 이 대화에서 병합·배포하지 않았다.
