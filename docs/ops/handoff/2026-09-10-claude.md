## 다음 세션 (선거 UI) — FEC 지출 데이터 → 지도 연결

사용자가 "선거 UI 세션에서 진행" 하기로 함. 이번 세션에서 사용자와 합의한 표시 규칙과
데이터 커버리지 한계를 여기 남긴다. 구현은 아직 안 함.

### 표시 규칙 (사용자 합의)

- **후보 단위로만 지지/반대 금액을 보여준다.** `candidates[].totals_by_category.super_pac`의
  `support_cents`/`oppose_cents`를 그대로 쓴다 (이미 후보별로 분리돼 있어 클라이언트 계산 불필요).
- **정당 단위로 지지·반대를 순액(net)으로 합치지 않는다.** 예비선거는 같은 당 후보가
  여러 명이라 합치면 의미가 깨지고, 지지 500만+반대 500만을 순액 0으로 표시하면
  "공방이 치열했다"와 "아무도 안 썼다"가 구분이 안 됨. 정당은 그룹핑(묶음 표시)에만 쓴다.
- **예비선거(P2026)/본선거(G2026)를 헤더에 명시**하고 섞지 않는다 — `election_types` 키로
  이미 분리돼서 온다.
- 기본 표시는 `category: super_pac`만 (계약 기본값). 나머지 6개 유형
  (`hybrid_pac`/`other_independent_spender`/`single_candidate_ie`/
  `state_independent_expenditure_committee`/`state_independent_spender_unclassified`/
  `unclassified`)은 펼치기로 제공.
- `status: "no_observed_records"`(null)와 실제 `$0`을 다르게 표시 — "데이터 없음" vs "$0".
- **"선거자금 모금액"이 아니라는 라벨을 반드시 붙인다.** 이 데이터는
  `measure_label_ko: "후보 대상 외부 독립지출 (캠프가 받은 후원금 아님)"` — 캠프 밖
  PAC/슈퍼팩이 지지·반대 목적으로 쓴 돈이지 후보가 모금한 돈이 아님. 헤더나 카드에
  상시 노출해야 오독을 막을 수 있음.

### 커버리지 한계 (반드시 UI에 노출)

`usa_election_finance_index_v1.json`에서 직접 확인한 값 (2026-09-09 기준):

- **2024 사이클: 연방 데이터 미수집** (`federal.status = "not_collected"`). 워싱턴주
  주지사 선거만 부분 확보(신고 11/29건, 나머지는 electioneering 등으로 제외).
- **2026 사이클: 연방 `partial`.** 14,408건 수집, 1,712건 제외
  (`candidate_office_conflict` 167 · `memo` 1,127 · `out_of_scope_office` 197 ·
  `unresolved_id` 220 · `unresolved_state` 1). 제외 건수를 각주로 노출할 것.
- **주지사 자동 수집은 워싱턴주 1곳뿐**, 나머지 47개 주 + DC는 없음. 주지사 카드는
  WA 외 전부 "데이터 수집 예정"으로 떠야 함.
- 워싱턴주 자체 한계(`limitations_ko`, 원문 그대로):
  - 워싱턴 C6 독립지출의 후보별 배분액만 포함, C4 등 다른 공시·선거 관련 통신 제외 →
    "전체 외부지출"이 아님.
  - 지출자 유형 미분류 — **워싱턴 데이터는 "슈퍼팩 지출"로 표기 금지** (연방 FEC 데이터는
    `category`가 분류돼 있어 이 제약이 없음. 주-연방 데이터를 같은 라벨로 섞어 쓰지 말 것).
  - 신고 연도가 선거일 연도와 다를 수 있어 예비/본선 시점이 이 자료만으론 확정 안 됨.
  - 주지사 후보 전체 명부 미확보 — 지출에서 식별된 후보만 포함(낙선/사퇴 후보 누락 가능).

### 발견한 데이터 이상 (착수 전 재확인 필요)

`usa_election_finance/2026/races/AK-house-00-*.json`의 `map_join.geometry_source`가
`"U.S. Census Bureau TIGERweb · 119th Congressional Districts · 2025-01-01 vintage"`로
찍혀 있음 — 그런데 실제 `congressional_districts/USA/AK.json`은 PR #281에서 120th
Congress 레이어로 이미 갱신됨. 이 `geometry_source` 필드는 FEC 파이프라인이 지도 파일을
읽어올 때 자기가 찾은 파일의 출처를 문자열로 박아 둔 것으로 보이는데, 지도 파일이
갱신된 뒤 금융 파이프라인이 재실행 안 됐으면 이 문자열이 실제와 어긋나 있을 수 있음.
착수 전에 재획정 8개 주(TX/NC/MO/OH/UT/CA/AL/TN/LA/GA)의 금융 데이터 파일에서
이 필드가 120th로 갱신됐는지 확인할 것 — 아니면 지도 UI가 구 선거구 경계 기준 지출을
새 경계에 잘못 얹을 위험이 있음.
