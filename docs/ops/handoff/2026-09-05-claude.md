### Not done / risks
- SheetJS는 jsdelivr에서 로드하는데 이 CDN이 조직 프록시 정책으로 막혀 있는 샌드박스도 있음(실제 배포 환경은 문제 없음). 처음 파일 업로드 시에만 로드하므로 그 CDN이 실제로 막힌 사용자 환경이면 "라이브러리를 불러오지 못했습니다" 에러가 뜸 — 발생하면 다른 CDN(cdnjs 등)으로 교체 고려.
- 헤더 자동 인식은 정규식 기반 근사 매칭이라, 종목명/수량/금액과 전혀 다른 헤더를 쓰는 파일은 "열을 찾지 못했습니다" 에러로 막힘 — 표준 템플릿 다운로드 제공은 안 함(요청 시 추가).
- 종목명이 로컬 레지스트리에도 없고 원격 검색에서도 안 잡히면 그 행은 통째로 스킵(안내 목록에만 표시) — 예: 국내 상장사 중 레지스트리에 없는 종목, 오타가 있는 종목명.
- **테스트 하네스 교훈**: Playwright `route.fulfill`로 이 파일의 스크립트/JSON 응답을 흉내낼 때 `contentType`에 `charset=utf-8`을 반드시 붙일 것 — 안 붙이면 파일 안의 한글 정규식 리터럴이 깨져서(예: "금액" → "ê¸ˆì•¡") 컬럼 탐지가 조용히 전부 실패한다. 실제 배포 서버는 정상 charset을 보내므로 프로덕션 버그는 아니었지만 여기서 몇 시간 삽질함.
- 실제 CDN에서 내려받은 진짜 SheetJS로는 검증 못 함(사샌드박스가 jsdelivr을 막아서 `XLSX.read`/`sheet_to_json` 두 호출만 스텁으로 대체). 라이브러리 자체의 실제 xlsx/xls 파싱은 신뢰하고 안 건드림 — 실제 엑셀 파일로 배포 후 한 번 확인 권장.
