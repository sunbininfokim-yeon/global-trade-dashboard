# 2026-10-10 미국 선거 반복 충돌 원인과 A 통합

사용자 요청: NE 중지. A줄을 먼저 최신 main에 맞추고, A가 main에 들어간 뒤 B줄을 처리한다. 개별 충돌 해결을 반복하지 않도록 프로젝트 구조를 보강한다. 병합·배포는 사용자 결정이다.

## 원인

주별 branch가 공용 검토 목록, 수집기, 전국 live/history/board/index와 TASKS를 동시에 수정했다. 주별 변경을 이전 주 위에 쌓는 동안 #489와 일일 bot이 같은 파일을 main에서 변경했다. 따라서 단순 재배치로는 다음 주 또는 다음 bot 수집 때 충돌이 재발했다. 특히 생성 JSON을 rebase하는 게시 절차는 실제 입력의 재검증을 보장하지 않았다.

## 실제 기준과 보존

- 새 통합 브랜치: `codex/election-state-integration-20261010`.
- 시작 main: 실제 fetch로 확인한 `6121acb4` (사용자 인수 당시 `d4e3fb97`보다 진행됨).
- A 입력: `origin/codex/nh-evidence-20261009`의 `9bf44183`와 그 조상 CT/AL/NJ/NM 변경. 병합 관계를 보존하되 공용 목록은 main 원본으로 유지한다.
- NE 작업은 기존 `us-ak-state-evidence-20261009`의 `codex/ne-state-evidence-20261010`에 보존했다. 그 작업을 실행·편입하지 않는다.
- B #508/#512는 수정하지 않았다. A가 main에 들어간 뒤 변환한다.

## 최종 구조

`config/state_evidence/2026/{CT,AL,NJ,NM,NH}.json` 다섯 입력에 주별 검토 변경·원래 API 부분 응답·원문 보완 입력과 수집 영수증을 분리했다. 검토 변경 134개는 모두 소유 주가 확인됐으며 미분류 변경은 없다. 공용 검토 JSON 9개는 시작 main과 동일하다.

`state_inputs.py`는 원래 기준 값의 해시를 검사해 현재 main의 다른 검토를 덮어쓰지 않는다. `polls.read`를 통해 기존 후보·여론조사·finance·board 빌더가 같은 유효 목록을 사용한다. #489의 메타데이터 정정과 A의 질문별 표본 정정 코드 모두 유지했다.

`refresh_state_polls --packet`과 `freeze_state_inputs.py`는 이후 주별 입력을 만든다. `check_state_packet_changes.py`와 AGENTS/작업 지침은 주별 PR의 공용 생성물·검토 목록·공용 수집기·TASKS 편집을 차단한다. 원문 허용 경로 등 공용 코드 보강은 별도 기반 PR에서 처리한다.

`publish_state_packets.py`는 원래 입력의 오프라인 재생성·검증용이다. 운영 수집은 오래된 입력을 먼저 게시하지 않는다. 성공한 최신 전국 수집에 역사적 검토 영수증만 보존하고 실제 조사 원문은 기존 수집기로 다시 확인한다. 실패하면 마지막 유효 자료를 유지한다.

`publish_polling_run.py`는 수집 체크포인트를 보존하고 게시 실패 시 최신 main에서 현재 검토 규칙으로 재생성한다. JSON rebase는 제거했다. 원문 확인 영수증과 원래 수집 시각을 유지하고 더 최신 전국 수집이 있으면 오래된 재시도를 보류한다. main의 일회성 Actions 작업 공간에서만 실행할 수 있다.

전국 생성 JSON은 로컬 미리보기에서 재생성해 확인하고 PR diff에서는 제외한다. 생성 JSON을 한 번 더 PR에 넣으면 다음 일일 bot 커밋과 재충돌하기 때문이다. 주별 원문 검토와 원래의 immutable 감사 스냅샷은 보존한다. 새 전국 산출물은 사용자 병합 후 기존 main polling workflow에서 생성·게시된다.
