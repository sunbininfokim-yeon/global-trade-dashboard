    함수 3개 생성 (전부 `create or replace`, 멱등)
- ❌ **반복 실패 (6회 연속, execute_sql 4회 + apply_migration 2회)**: 정확히 아래 문장에서만
  60초 타임아웃.
  ```sql
  drop trigger if exists mail_report_keep_latest on public.mailing_reports;
  create trigger mail_report_keep_latest before update on public.mailing_reports
    for each row execute function public.mail_report_keep_latest();
  ```
  - 타임아웃마다 즉시 확인: 트리거 미적용(`pg_trigger`에 없음), `pg_locks`/`pg_stat_activity`에
    해당 3개 테이블(`mailing_reports`,`mailing_outbox`,`mailing_deliveries`) 관련 락이나
    활성/idle-in-transaction 세션 전혀 없음 — 다른 트랜잭션이 막은 게 아님.
  - `set local lock_timeout='5s'`를 걸어도 동일하게 60초까지 하이힝 (lock_timeout은 락
    대기 시간만 제한하므로, 락 경합이 아니라면 효과가 없는 게 당연함).
  - 같은 세션에서 다른 테이블 대상 DDL(함수 3개 생성)은 전부 즉시 성공 — `mailing_reports`에
    대한 이 특정 `CREATE TRIGGER`만 문제.
  - `pg_publication_tables`에 `mailing_reports` 없음 (Realtime publication 아님),
    `pg_class.relpages=23/reltuples=169`로 테이블 자체는 작음 — 크기 문제 아님.
  - postgres 로그에 이 시간대 체크포인트 쓰기가 246~269초 걸린 기록이 있어, 이 운영 DB가
    다수의 자동 수집 workflow로 인해 쓰기 I/O가 상당히 밀려 있을 가능성이 있음 — 락 대기가
    아니라 커밋/WAL flush가 I/O 뒤에 밀려 지연되는 것으로 추정되나 확진은 못 함.
  - MCP 도구 자체의 클라이언트 쪽 60초 캡일 가능성도 배제 못 함 (Postgres
    `statement_timeout`은 2분으로 별도 확인했으나 MCP 호출은 매번 60초에서 끊김).
