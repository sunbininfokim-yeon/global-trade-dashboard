**막힌 지점 두 개 (Claude 가 못 한 이유).**
1. `review_receipts.json` 이 입력 5개의 해시를 묶어 두어서 입력만 바꾸면 `ValueError: review receipt does not match input` 로 거절된다. 새 증거일·해시·새 출처 확인 기록은 출처를 직접 연 쪽이 쓴다.

**검증기 규칙 불일치 (결정 필요).** `election_watch/israel_analysis.py` 의 `validate_observations` 는 `accepted` 의석 조사에
`field_end`·`pollster`(비어 있지 않음)·`n_respondents`(양의 정수)를 요구한다(`accepted seat poll requires methodology and field date`).
`maariv-panel4all-2026-10-15` 는 Cursor 가 `accepted` 로 올렸지만 `pollster: null` 이다. Cursor 메모: "기사에 연구소 이름이 없다. Panel4All 인터넷 패널만
나온다. 집계 사이트는 같은 날짜를 Lazar 라고 부르지만 그 이름은 복사하지 않았다." 즉 두 에이전트의 정책이 다르다.
Cursor = 패널·표본·기간이 있으면 채택, Codex 검증기 = 조사기관 이름이 있어야 채택. 이 행을 `accepted` 로 두면 생성이 실패한다.
Claude 가 이 한 행만 메모리에서 `partial` 로 바꿔 돌려 보니 **나머지 입력은 내용 검증을 모두 통과**했다.
