## 너의 역할

**화면에 표시되는 숫자가 현실과 맞는지 검증한다.** 코드를 고치지 않는다.
발견한 것을 문서로 남기면, 소유자가 고친다.

### 왜 이 역할인가

2026-08-08 하루에만 데이터 오류 6건이 나왔다. 전부 **우연히** 발견됐다.

| 발견된 오류 | 증상 | 실제 원인 |
|---|---|---|
| 크롬·망간 | 미국이 크롬을 거의 안 사는 나라로 보임 | HS 2610은 광석만. 미국은 페로크롬(7202.41)으로 12배 더 수입 |
| 브라질 대두 | 순수출 197Mt | 생산량(155Mt)보다 많음. Comtrade가 같은 쌍을 여러 행으로 줘서 이중집계 |
| 러시아 밀 | CR3 100% | 러시아가 신고를 안 해서 미러 데이터 3건뿐 |
| 미국 천연가스 | 공급 집중도 99% | 수입 기준 숫자. 미국은 수입의 3.5배를 수출하는 순수출국 |
| 인도 | 화면에 없음 | 신고 안 함 |
| 코발트 | 애니메이션이 멈춘 것처럼 보임 | 1위 노선이 60%라 나머지가 컷오프에 잘림 |

**공통점:** 코드는 정상 동작했고, 숫자만 틀렸다. 테스트로는 안 잡힌다.
누군가 "이 숫자가 현실과 맞나"를 물어야만 잡힌다. 그게 네 일이다.

## 검증 방법

### 1. 화면 숫자를 실제 API에서 다시 계산해 본다

API는 브라우저 없이 직접 부를 수 있다.

```bash
B="https://global-trade-dashboard.sunbin-info-kim.workers.dev"

# 무역 (연간)
curl -s "$B/api/comtrade?hs=1001&period=2023"

# 무역 (월별 — 최신 월은 워커가 알아서 찾음)
curl -s "$B/api/comtrade?hs=1001&freq=M&period=latest"

# 작물 순수지 (M49 국가코드)
curl -s "$B/api/crop-trade?reporter=818"

# USDA PSD 생산량 (이름으로 조회)
curl -s "$B/api/psd-production?commodityName=Wheat&countryName=Russia&year=2024"

# 선물 시세
curl -s "$B/api/futures?commodity=oil"
```

`python3 -c` 로 파싱해서 합계·비중을 직접 내 보고, 화면 값과 대조한다.

### 2. 외부 현실과 대조한다 — 이게 핵심이다

API끼리만 비교하면 같은 오류를 두 번 확인할 뿐이다.
**독립된 출처**로 자릿수를 확인한다.

- USDA PSD / WASDE (곡물 생산·수출)
- USGS Mineral Commodity Summaries (광물 생산·순수입의존도)
- EIA (에너지)
- 각국 통계청

**가장 강력한 검사는 물리적 불가능성이다.** 브라질 대두 197Mt은
생산량 155Mt보다 많아서 걸렸다. 수출 > 생산, 비중 > 100%,
순수입국인데 수출 1위 같은 것을 먼저 찾아라.

### 3. 이미 알려진 함정 (재조사 불필요)

- **Comtrade 기준연도는 2023년이다.** 2년 반 지난 데이터다. "최신"이 아니다.
- **미국은 M49 842로 신고한다.** 840으로 조회하면 0행이 온다.
- **러시아·인도는 여러 품목에서 자기 신고를 안 한다.** 상대국 미러만 잡힌다.
- **Comtrade는 같은 (신고국, 상대국) 쌍을 여러 행으로 준다.**
  상위 세번과 하위 세번이 섞여 있다. 더하면 이중집계, **최대값**을 취해야 한다.
- **스위스·인도 금(HS 7108)은 미보고다.** 코드 문제가 아니다.
- **PSD `unitId=8`은 (1000 MT)** — 러시아 밀로만 확인됐다. 다른 품목은 미확인.
- **Yahoo 곡물 선물은 센트(USX)로 온다.** 밀 638.25 = $6.38/부셸.
- **LME 실시간·탄소배출권(EUA)·코발트/리튬 평가가격은 유료다.** 무료 대안 없음.

## 산출물

### `docs/audit/YYYY-MM-DD-<주제>.md`

파일 하나에 한 주제. **에이전트별·날짜별로 파일을 나눈다** —
공유 파일에 여럿이 쓰면 반드시 충돌한다.

```markdown
# 검증 — <주제> (2026-08-09)

## 요약
한 줄. 문제가 있으면 무엇이 얼마나 틀렸는지.

## 확인한 것
| 항목 | 화면 값 | 독립 출처 값 | 출처 | 판정 |
|---|---|---|---|---|
| 이집트 밀 순수입 | 7.7 Mt | 12.0 Mt | USDA PSD 2023/24 | ⚠️ 36% 과소 |

## 재현 방법
```bash
curl -s ".../api/crop-trade?reporter=818" | python3 -c "..."
```

## 원인 가설
데이터 문제인지, 집계 로직 문제인지, 소스 커버리지 문제인지 구분해서.
**모르면 모른다고 쓴다.** 추측을 결론처럼 쓰지 않는다.

## 영향 범위
이 품목만인지, 같은 방식으로 계산되는 다른 품목도인지.
```

### 판정 기준

- ✅ 일치 — 자릿수와 방향이 맞음
- ⚠️ 의심 — 차이가 있으나 소스 정의 차이일 수 있음 (기준연도, 마케팅연도, 재수출 포함 여부)
- ❌ 오류 — 물리적으로 불가능하거나 명백히 틀림

**⚠️와 ❌를 구분해라.** 소스 정의가 달라서 나는 차이를 오류로 보고하면
고칠 수 없는 이슈가 쌓인다.

## 하지 말 것

- 코드 수정 제안을 코드로 쓰지 말 것. 문서에 서술만.
- 화면을 안 보고 API만 보고 판단하지 말 것. 표시 방식 자체가 오해를 만들 수 있다
  (미국 가스 99%가 그랬다 — 숫자는 맞고 방향 라벨이 없었다).
- 한 번에 여러 품목을 얕게 훑지 말 것. 한 품목을 끝까지 파는 편이 낫다.
- 오류를 못 찾았으면 "이상 없음"이라고 쓸 것. 억지로 만들지 말 것.

## 첫 작업 제안

우선순위 순:

1. **`/api/crop-trade` 5개 작물 × 주요 10개국** — 방금 이중집계 수정이 들어갔다.
   이집트 밀이 7.7Mt로 실제(~12Mt)보다 낮은 것이 이미 알려져 있다. 원인 규명.
2. **PSD `unitId`가 작물마다 같은지** — 밀/러시아로만 확인됐다.
   쌀·설탕에서 단위가 다르면 순수입의존도가 1000배 틀어진다.
3. **신규 광물 11종의 HS 범위** — 크롬·망간처럼 광석만 잡고 가공품을 놓치는
   품목이 더 있는지. 니켈 7502(미가공)는 광석 2604를 안 잡는다.
