# 본회의 단계 표시와 즐겨찾기 점검 (2026-09-28)

## 확인한 동작

- H.R. 3633의 2026-09-15 상원 표결은 심의 개시 동의에 대한 토론종결 표결이다. 찬성 49, 반대 50으로 부결됐으며 최종 법안 통과 표결의 부결로 표시하면 안 된다.
- 공식 근거: https://www.senate.gov/legislative/LIS/roll_call_votes/vote1192/vote_119_2_00234.htm
- 운영 사이트에서 로그인 상태로 별 클릭 → 저장 완료 표시 → 마이페이지 법안 카드 표시를 확인했다. 이번 점검에서는 저장 실패가 재현되지 않았다. 서비스 롤 조회만으로 RLS가 정상이라고 판단한 것이 아니라 실제 로그인 브라우저 경로도 확인했다.
- 즐겨찾기는 브라우저의 Supabase Auth 세션으로 `user_favorites`를 읽고 쓴다. 복합 키는 `(user_id, item_kind, item_id)`이며 법안 상세는 별도의 Worker API에서 읽는다. 따라서 상세 로딩 실패와 즐겨찾기 저장 실패는 구별해야 한다.

## 변경

- `floorSetback`은 표시 전용 함수다. 실패한 절차/통과 표결을 해당 원의 본회의 단계에 빨간색과 설명으로 표시한다. 나중에 본회의를 통과한 경우 빨간 표시를 제거한다. 법안 단계·알림 스냅샷은 변경하지 않는다.
- 클래리티 표시: `상원 본회의 통과` 단계 빨간색, 설명 `심의 개시 토론종결 부결`. 마이페이지 카드에도 같은 설명을 표시한다.
- 즐겨찾기 저장 오류를 사용자에게 알리고 성공으로 표시하지 않는다. 저장된 법안 제목은 상세 API를 기다리지 않고 먼저 표시한다.
- Auth 이벤트에서 Supabase 조회 리스너를 다음 작업으로 미뤄 인증 잠금 안에서 재진입하지 않게 한다. 이는 예방적 보강이며 이번 운영 증상의 확정 원인이라고 주장하지 않는다.
- 세션 복원 전에 마이페이지를 연 경우에도 로그인 이벤트를 구독해 다시 표시한다. 떠난 화면의 뒤늦은 상세 조회 실패가 새 화면을 덮어쓰지 않게 한다.
- Supabase 참고: https://supabase.com/docs/guides/troubleshooting/why-is-my-supabase-api-call-not-returning-PGzXw0

## 검증 및 배포 범위

- Node 테스트: 기존 입법 단계·Worker 20건 + 신규 UI/인증/즐겨찾기 6건 통과.
- 최신 main에 적용한 별도 패치에서도 신규 6건 통과. 로컬 브라우저에서 상원 빨간 표시와 부결 설명 확인.
- 저장소의 기존 CSS `is-failed` 사용. SQL/RLS/법안 상태 및 메일 발송 코드 변경 없음.
- auth/policy-evidence/policy/mypage의 캐시 버전 갱신. 최신 main 기반 PR로 제공하며 운영 배포는 별도다.
