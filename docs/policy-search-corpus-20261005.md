# 정책 검색: 공식 본문과 인용 관계를 포함하는 공통 색인

제목·요약에 벡터가 있어도 해당 문서가 주제 검색에 나타난다는 보장은 없다. 요약이 없는 결의안이 행정명령 번호만 인용하면, 제목·요약 검색으로는 그 행정명령의 국가·관세 주제를 확인할 수 없다. 특정 법안의 제목을 덧붙이는 대신 네 자료 유형에 같은 검색 계약을 적용한다.

## 원본과 검색 자료의 분리

`bills`, `public_laws`, `executive_orders`, `regulations`는 기존 식별자·단계·즐겨찾기 연결과 벡터를 유지한다. 검색 전용 자료는 다음 세 테이블에 저장한다. 이 구조의 쓰기는 법안 단계나 메일 이벤트를 변경하지 않는다.

| 테이블 | 저장 내용 |
|---|---|
| `policy_search_documents` | 유형+원본 ID, 공식 제목·요약·정책 주제·본문, 공식 URL, 명시적 인용, 입력 해시·수집 범위 |
| `policy_search_passages` | 문단, 근거 필드·URL, 인용 대상, 문단 해시, Gemini 모델·벡터·생성 시각 |
| `policy_search_jobs` | 문서별 갱신 revision, 우선순위, 처리 상태, 소유 토큰·lease, 재시도 |

기존 Gemini 모델 `gemini-embedding-001`, 1536차원을 유지한다. 문서는 `RETRIEVAL_DOCUMENT`, 질문은 기존 Worker의 `RETRIEVAL_QUERY`를 쓴다. PostgreSQL은 벡터 저장·거리 계산을 담당하며 임베딩 생성은 Gemini API에서 수행한다. 모델 또는 차원을 바꾸려면 별도 색인 버전과 재계산이 필요하다.

## 무엇을 읽고 어떻게 근거를 표시하는가

- 법안: 공식 제목·CRS 요약·정책 주제·공식 텍스트 버전. DB에 URL이 있어도 Congress.gov의 text endpoint를 source revision별로 확인해 더 최신 버전을 우선한다. 공식 목록이 비어 있을 때만 기존 DB의 확보된 공식 버전을 읽는다.
- 제정법: GovInfo의 원래 제정법 본문. 신규 공법의 URL·package ID가 아직 DB에 없으면 공법 번호로 공식 GovInfo package를 확인한다. 원문이 미발행이거나 GovInfo 오류 안내로 이동하면 연결된 공식 의회 페이지의 제목·요약만 보관하고 `text_status=unavailable`로 표시한다. 연결 법안의 본문을 제정법 본문으로 대체하지 않는다. 현재 U.S. Code의 모든 개정 사항을 통합한 현행법 본문이라는 뜻은 아니다.
- 행정명령: 기존 공식 원문 캐시, 또는 GovInfo 공식 원문. 번호만 저장한 행과 본문을 확보한 행을 구분한다.
- 규정: GovInfo Federal Register 문서와 기관의 abstract.

문서에 명시된 EO·Public Law 번호만 관계로 연결한다. 본문이 인용한 문서의 제목·요약·일부 본문을 `cited_document`로 저장하고, 인용 원문 URL과 대상 문서 URL을 모두 남긴다. 의미가 비슷하다는 이유로 법적 근거·폐지·제정 관계를 생성하지 않는다. 대상이 없는 인용도 미해결 상태로 남긴다. U.S. Code/CFR 조항 관계 확장은 이 색인에 아직 포함하지 않았다.

공식 텍스트 요청은 최소 1.2초 간격으로 실행하고 캐시한다. 요청당 최대 5MB, 본문 보관은 최대 100만 문자다. 더 긴 본문은 `partial_body`로 표시한다. 벡터는 문서당 최대 24개이며 제목·요약·주제와 인용 맥락을 확보한 뒤 본문의 처음·중간·끝에 분산한다. 모든 문단을 임베딩하지 않은 문서는 `embedding_coverage=partial`이다. 본문 단어 검색은 이 대표 문단에 한정되지 않고 보관된 본문 전체를 읽는다. 전체 원문 임베딩 완료로 오해하면 안 된다.

## 검색 계약

번호 정확 검색 → 공식 본문·제목·요약·주제·인용 근거 검색 + 문단 의미 검색 → 기존 문서 벡터 검색 fallback 순으로 결합한다. 미전환 문서는 기존 검색을 유지한다. 새 RPC가 없어도 기존 검색이 작동하며, 문단 벡터는 문서별 최대 유사도로 합쳐 중복 결과를 제거한다.

복수 조건은 근거를 확인한 개수로 정렬한다. 예를 들어 H.J.Res.72의 ‘캐나다, 관세’ 일치는 자신이 인용한 EO 14193의 맥락이므로 `field=cited_document`와 두 공식 URL을 반환하고 UI에 ‘인용 문서 맥락 포함’을 표시한다. 자기 본문에서 두 조건을 충족했다는 뜻이 아니다.

근거가 없고 의미 유사도만 있는 후보는 ‘의미상 관련 · 조건 근거 미확인’으로 구분한다. 현재 0.65는 후보 표시를 위한 임시 하한이며 법적 관련성이나 AND 충족의 기준이 아니다. 별도 평가 자료로 조정할 필요가 있다. 한국어 별칭 사전은 국가·관세·광물·수출통제·암호화폐 등 제한된 범위다. 모르는 표현을 자동 번역해 일치했다고 주장하지 않는다.

검색 결과는 기존 네 분류와 관련도·날짜 정렬을 유지한다. `condition_matches`에는 단어 근거와 인용 출처가, `search_coverage`에는 본문·문단의 범위가, `search_refresh_pending`에는 갱신 대기 여부가 들어간다. 본문이 없으면 ‘공식 본문 미확보’를 표시한다. `embedding_coverage=complete`는 확보한 입력의 문단을 모두 임베딩했다는 뜻이며 미확보된 공식 본문까지 처리했다는 뜻이 아니다. 공개 응답에는 전체 본문이나 벡터가 전달되지 않는다. 의미 검색만 사용한 결과에는 문서별 본문 근거 창이 없을 수 있다.

## 변경 감지와 재개

원본 제목·요약·날짜·source timestamp, 법안 텍스트 버전·주제가 바뀌면 문서별 job을 갱신한다. 연결 법안 요약이 바뀌면 공법도 갱신한다. 인용 대상이 바뀌면 기존 검색 문서의 인용 관계를 따라 한 단계의 인용 문서를 갱신한다. 실제 원문 수집기는 별도로 새 자료를 DB에 가져와야 한다. 색인기는 인터넷 전체에서 새 법안을 발견하는 수집기를 대체하지 않는다.

살아 있는 변경은 우선순위 20, 초기 적재의 최신 회기·최근 EO·규정은 10, 과거 자료는 0이다. `FOR UPDATE SKIP LOCKED`와 15분 lease를 사용하고, 작업 중 새 revision이 들어오면 오래된 결과의 저장을 거부한다. 변경되지 않은 문단의 해시·모델이 같으면 벡터를 재사용한다. 끝나지 않은 작업은 다음 실행에서 재개한다. 실패는 제한된 재시도 후 운영 점검 대상으로 남는다. 변경이 다시 들어오면 소진된 시도 횟수도 초기화한다.

원문이 없는 완료 문서는 마지막 색인으로부터 24시간이 지난 뒤 매 실행 최대 25건만 재확인한다. 비어 있는 Congress 공식 텍스트 목록 캐시는 24시간 뒤 만료시켜 원본 revision이 같아도 다시 확인한다. 신규 공법·법안의 본문이 뒤늦게 발행되어도 원본 메타데이터 변화에만 의존하지 않고 원문 확보를 시도한다. 대기·처리·실패 상태의 작업은 이 보강 대상으로 선택하지 않으며, 변경 없는 문단 벡터는 재사용한다. 재확인이 공식 원문 발행을 보장하지는 않는다.

RLS와 권한 회수로 새 테이블/RPC를 `anon`·`authenticated`에 공개하지 않는다. Worker는 기존 서비스 자격증명으로 제한된 검색 응답을 만든다. 원본 데이터 삭제 시 해당 검색 자료만 제거하며 다른 문서와 즐겨찾기·메일 연결을 삭제하지 않는다.

## 맥 운영

비공개 환경 파일을 읽는 로컬 실행기:

```sh
cd /Users/yeoninair/Documents/policy-search-corpus-20261005
/opt/miniconda3/bin/python3 scripts/run-policy-search-local.py --bootstrap
caffeinate -i /opt/miniconda3/bin/python3 scripts/run-policy-search-local.py --limit 1000 --max-minutes 60
```

`--bootstrap`은 기존 완료 job까지 포함해 중복 등록을 피한다. 명시적 재계산은 `--enqueue bill:119-hjres-72` 등으로 수행한다. `--seed --types ... --after ...`는 관리자가 지정한 일부 문서를 다시 등록하는 도구이므로 전체 적재에는 `--bootstrap`을 쓴다. `--text-only` 결과는 임베딩 완료로 처리하지 않는다.

기존 맥 서비스 `/Users/yeoninair/Documents/policy-mac-handoff-20260930`에 이 파일들과 `searchCycle` hook을 설치했다. 런타임 hook 커밋 `93801ecd` 및 입력 정규화·최신 원문 보완 `864ffa3e`/`8a8b369c`는 Congress incremental → RSS 보관 → 검색 색인 갱신 순서로 연결한다. 수집은 사이클 완료 후 4시간 대기하며, 색인은 한 번에 최대 1,000건/약 60분의 작업 경계로 제한한다. 독립 초기 배치가 종료된 뒤 기존 맥 서비스의 실제 자동 색인 사이클을 확인했다. 전역 검색 잠금으로 둘이 같은 색인 배치를 동시에 돌리지 않는다. RSS 보관이나 Congress 수집이 실패해도 기존 대기열의 색인은 독립적으로 시도한다. Mac driver의 본문은 이 PR 범위 밖의 기존 런타임 브랜치에 있다. 재적용 가능한 driver 변경은 `docs/policy-search-mac-hook.patch`에 보관했으므로 추후 해당 driver를 업데이트할 때 이 hook을 보존해야 한다. 신규 공법 출처·일일 재확인 보강은 런타임 `a3e9add6`/`aa38cd8f`/`60603095`에도 설치했다.

`POLICY_SEARCH_ENABLED=false`로 hook만 끌 수 있다. 검색 캐시 디렉터리의 `STOP`, 또는 기존 Mac 수집기의 `STOP`이 있으면 새 문서를 처리하지 않는다. 과거 `continuous/STOP` 파일은 다른 실행기의 제어 파일이다. 새 임베딩은 기존 비공개 Google AI Studio 키를 사용한다. 원문 403/429 또는 Gemini quota 오류는 해당 배치를 중단하고 재시도로 남기며 차단 회피를 하지 않는다. 실패 시각은 성공 시각으로 기록하지 않는다.

DB 사용량은 25건마다 검사하고 기본 6GiB에 도달하면 색인을 중단한다. 이는 프로젝트의 실제 청구 한도를 자동 조회하는 기능이 아니라 Pro 8GB에서 여유 공간을 남기기 위한 운영 상한이다. 상한을 바꾸기 전에 `policy_search_status().database_bytes`와 디스크 한도를 확인해야 한다. 원문과 벡터를 무제한으로 채우지 않는다.

## 적용·검증 기록 (2026-10-05~06 KST)

마이그레이션 `supabase/migrations/20261005010000_policy_search_documents.sql`을 운영 DB에 적용했고 `schema.sql`에 동일 구조를 반영했다. 기존 법안 상태·메일 테이블을 선행 조건으로 요구하지 않는다. 기존 벡터는 변경하지 않았다. 적용 SQL과 사전 DB 규모는 비공개 `policy-downloads/search-corpus-20261005/backup/`에 보관했다.

초기 5개 문서에서 59개 실제 Gemini 문단 벡터가 저장됐다. 긴 CLARITY 본문은 약 65만 문자를 보관하며 24개 문단 벡터로 부분 범위를 표시했다. 이후 26,692개 기존 문서를 초기 대기열에 등록하고 첫 배치를 시작했다. 이는 26,692개 임베딩 완료라는 뜻이 아니다. 실제 최신 수치는 `policy_search_status()`를 조회한다.

검색 코드의 main 병합·사이트 배포는 아직 수행하지 않았다. 운영 DB 검색 성공과 웹사이트 반영은 별개의 단계다. 수요일 배포 전 이 검색 PR을 검토하고 기존 PR #321의 캐시 버전 및 Mac driver와 연결을 조정한 뒤 실제 사이트에서 일반 주제·복수 조건·네 자료 유형의 결과를 확인한다. 메일 Worker의 발송 설정은 이 작업에서 변경하지 않았다.

CI `Ownership guard`는 `codex/*` 브랜치의 `_worker.js`와 `New for anti/index.html` 변경 때문에 실패한다. 이는 테스트 실패가 아닌 소유권 검사이며, 사용자가 승인한 검색 범위에 대해 Claude가 두 파일을 검토·통합할 수 있도록 준비한 상태다. 브랜치 접두사 변경이나 검사 규칙 변경으로 우회하지 않았다. 배포 담당자는 현재 main 및 PR #321과 함께 검색 연결·캐시 버전을 검토해야 한다.
