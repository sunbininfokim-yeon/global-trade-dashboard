## 검증과 재실행

운영 Supabase를 읽는 현재 로컬 API handler에서 확인했다. 배포 화면 검증 결과는 아니다.

- `116/PMK.04` + coal: 신규 문서 1건.
- `석탄, 세금감면` + coal·AND: 5건, 116/2019 포함.
- `석탄, 수출` + coal·AND: 15건. Permendag 15·KMK 31·PMK 51에 선택 조문 연결.
- 116/2019 context 및 51/2025 상세: HTTP 200, 관계·적용범위·본문·효력 근거 확인.
- review/effect pack 재적용: 신규 0건. Python 수집·목록 검사 31개, Node API·분리·링크·임베딩 계약 검사 16개 통과.

최종 원문 대조에서 이번에 삽입한 PP 18의 경과조치 표제 `Pasal 17 ayat (8)`를 `Pasal 16 ayat (8)`로 바로잡았다. 외부 FK가 없음을 확인하고 기존 행 내용 전체 일치를 조건으로 제한 트랜잭션에서 잘못된 ID를 제거하고 수정된 내용 해시 ID로 재삽입했다. 총수는 33건으로 유지된다. 수정 전 입력은 비공개 `coal-review/before-article-label-correction.json`에 보관했다. 최종 pack에는 올바른 표제·ID만 포함한다.

```sh
node scripts/indonesia_policy/import-review.cjs scripts/indonesia_policy/coal-review-pack-20261020.json --env-file /ABSOLUTE/ENV
node scripts/indonesia_policy/import-legal-effect.cjs scripts/indonesia_policy/coal-legal-effect-pack-20261020.json --env-file /ABSOLUTE/ENV
```

기본은 미리보기, 실제 저장은 명시적 `--write`가 필요하다. DB가 인용·현재 원문 해시·URL을 검증하며 동일 입력 재실행은 중복을 만들지 않는다. 새 DB에는 원문 문서를 먼저 저장해야 한다. 스키마 변경이 없어 새 migration은 없다. 공간 부족 상태에서 PGlite 설치·migration 전체 재실행은 하지 않았다.
